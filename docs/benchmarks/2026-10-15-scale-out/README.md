Hosted, 2026-10-15, 18:27–21:17 UTC. Plan: [`SCALE_OUT_PLAN.md`](../../SCALE_OUT_PLAN.md). The baseline is this morning's run on the
same repository, [`2026-10-15-100-agents`](../2026-10-15-100-agents/README.md) (`fixed3`).

## Setup

- **Deployment:** `https://demo.gitgolf.mjtechguy.com`, Cloudflare-native Golf: a Worker, a Workspace Durable Object, D1 (primary in
  `ENAM`) and Artifacts.
- **Repository:** `mj/agent-bench-3`, with agentic mode on: low-risk `docs/**`, landing without a person, required check
  `bench/ci`.
- **Load:**
  - `scripts/agent_speed_bench.mjs`, five processes from one workstation, `--think 60` (each agent pauses 30–90 s between
    operations);
  - the same scenario mix as the baseline, scaled by agent count;
  - S7 reports `bench/ci` itself (`GOLF_BENCH_CI_TOKEN`).
- **Probes, every 20 s:**
  - a clone advertisement;
  - an MCP call to an unknown tool, which the Workspace admits as exclusive. Its `queue` Server-Timing is the Workspace's admission
    wait (`data/*-workspace-probe.txt`).

## What each step changed

**S1 (`s1a`, about 30 agents).**
- Reads left the queue: clone p50 2.7 s, `ls-remote` 2.3 s, fetch 1.5 s.
- Writes still waited in it: push p50 21.9 s; Workspace operations queued 6–11 s.

**S2 (`s2a`, `s2b`, about 30 agents).**
- Push p50 21.9 s → 1.8 s; Source API commit 10.7 s → 1.5–1.8 s; S7 commit 8.2 s → 1.6 s. None of them wait in the queue.
- Landing got worse (16 of 23, then 11 of 18). That led to the next finding.

**Merge bases (`s2c` → `s2d`).**
- `comparison()` read up to 500 commits of each tip's ancestry whenever the base had moved by a merge. This repository is past that
  size.
- Every pull request whose base had moved failed its landing evaluation with `resource_exhausted`, and `autoLand` skipped it
  silently.
- At about 60 agents, 15 of 23 pull requests timed out with passing checks.
- After the fix, #530 landed at the first sweep, 18 minutes after it opened.

**S3 MCP (`s2d`).** `get_pull_request` polling was most of the Workspace's load (871 polls against 23 opened pull requests at
about 60 agents). Served by the Worker, `open_pull_request` waited 1.6 s at p50 instead of 18.6 s.

**Busy merges (`s2d` → `s2e`).**
- At about 110 agents, Artifacts answered some merges with `ERR artifacts_git_receive_pack_busy`.
- The journal kept each as an unknown outcome, which fenced the whole repository until maintenance: two to seven minutes.
- D1 showed writes in bursts with four-minute gaps. Pushes failed 233 of 325, refused as "finishing a merge"; commits gave up 263
  of 406.
- After the fix the provider still answered busy, twice in the first eight minutes, but each merge was settled and retried at once.
  Writes ran at 48–67 a minute, every minute.

## Remaining

- **Landing timeouts:** 38 of 149 pull requests in `s2e`.
- **`open_pull_request` errors:** 14 calls were tool errors of two kinds: "An unresolved operation fences further changes" (a merge
  held the repository) and "The selected discussion or commits changed".
- **Distance to D1:**
  - Each D1 call from the Worker took about 100 ms; from the Workspace, next to the primary, about 20 ms.
  - Requests landed in Seattle or Dublin.
  - Smart Placement would bring the Worker next to D1.
- **Rare transport failures in `s2e`:**
  - three `Connection reset by peer`;
  - ten pushes ending in "unexpected disconnect while reading sideband packet" (five in S1, five in S2);
  - one fetch answered without a packfile.
  None is investigated yet.
- **Expensive D1 reads:** around 19:56, D1 read 0.7–1.3 million rows a minute, which points to unindexed scans in a sweep.

## Landing: the last 20 % (2026-10-16, 23:54–00:23 UTC)

- **Diagnosis run `s2i`** (S7 only, 16 agents, 5 min): 36 of 48 pull requests landed.
  - The 12 others had a passing check, and the live landing evaluation said `land`.
  - They had no land operation at all.
- **Cause:** `landSoon` listed open pull requests in the sweep's fixed order, limited to 200, and the repository had 359 open (most of them stale bench pull requests). Every stuck one ranked 206–326.
- **Fix (#143):** a targeted pass starts from the branches at its commit.
- **After the deploy, `s2j`** (the same run): **71 of 71 landed, p50 5.9 s, p95 11.5 s.**
