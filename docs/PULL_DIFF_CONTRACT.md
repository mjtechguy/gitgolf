# PR changed files and shared diff workspace

`RepositoryService/GetPullRequestDiff` requires the target repository, exact native `repositoryId` and `pullRequestId`, PR number and complete lowercase `baseCommitId`/`headCommitId` selected from PR detail. Native IDs are positive canonical signed64 decimal strings; number is1–2147483647, and both object IDs are full40/64-character values of equal width. This development-contract strengthening deliberately refuses old requests without native IDs rather than interpreting a name/number as the displayed target.

The current caller/base repository/native PR must match those IDs and selected branch-tip/head objects. The base repository's retained `refs/pull/NUMBER/head` is checked before and after the bounded native `.diff` read. Native PR IDs, refs, base/head objects, source repository, state, merged flag and `merge_base` are reobserved after the read, followed by current repository/session authority. A15-second child context bounds the complete read. Responses use `no-store`; browser sessions and explicitly allowlisted read-only Golf API credentials retain native repository permission checks.

The response echoes both native IDs and the selected base-tip/head, plus **`mergeBaseCommitId`**, the native old-side comparison object. The PR metadata exposes this separately and can leave it empty while unavailable; the diff requires a valid nonempty object. Never substitute today's base branch tip or a child blame commit for the merge base. For a diverged target B and source H with common M, the displayed diff is M→H even though `baseCommitId=B`. CLI/MCP reads return that same receipt; neither automatic object lookup nor a fabricated pager is added.

Output is native UTF-8 PR merge-base diff, at most512KiB with an exact byte count. Larger, malformed encoding/control, unexpected content-type/status or inaccessible output fails without partial text. Changed target, comparison, retained ref or merge base returns `failed_precondition`; explicitly refresh metadata to select a new comparison. These checks are observations, **not atomic locks**, proof of patch completeness, elimination of ABA races, validated provider-cache internals or merge authorization. The native merge-base value is an observed comparison field, not trusted policy evidence.

A base-repository reader can inspect the retained PR diff without general private-fork access. `make qualify-pull-workspace` retains that earlier proof and now supplies the required IDs. `make qualify-pull-diff-binding` is the new exact-comparison fixture: a renamed private fork, diverged base tip, supported Git clone/fetch and independent merge-base/blob/diff observations, API/CLI/PAT-bearer MCP, wrong-target/head/private/Origin denials, both themes/mobile, live access revocation and stale target after movement. Final served execution and image provenance belong in the [implementation ledger](IMPLEMENTATION_STATUS.md); implementation/fixture results alone do not qualify the deployed path. No source/imported workflow, inference or remote push runs; all owned actors/repos/sessions are removed.

The canonical Files changed URL is `/OWNER/REPOSITORY/pull/NUMBER/files`; legacy `?view=pulls&pull=N&pullView=files` remains readable. PR/commit views share a client parser and global diff layout. Files navigation/search, native header collapse, literal source rows, old/new line anchors, unified/split, rename/delete/binary notices and session Viewed use the selected comparison. Browser query identity includes actor, native repository/PR IDs and base-tip/merge-base/head; anchors and Viewed additionally bind actual old/new objects. A displayed old-side mismatch with the returned receipt hides the diff instead of silently replacing the selection. The compact metadata distinguishes actual old side/head and a divergent target tip.

The client parser is for rendering, not server write admission. Source lines such as `+++ b/another-file` inside a hunk cannot invent a file. Git C-quoted UTF-8 names and zero-length ranges are supported. Invalid hunk counts retain native text rather than fabricating line numbers. More than500 files or12,000 rows falls back to the complete bounded native text. Viewed is private in-memory state, resets on comparison/unmount and is not a durable review/approval. Display preference storage contains no private paths or text.

Paths, code and metadata never execute as HTML. Side/line anchors identify that selected comparison, not missing context outside the patch or current relocated comments. Split alignment preserves patch text. Native output stays explicitly expandable. Correct server-side coordinate admission, encrypted original comparison/draft retention, inline batch publication/replies/resolution/suggestions, whitespace/context/range comparison, durable Viewed, larger-patch performance and protected merge remain required. The [inline implementation design](INLINE_REVIEW_IMPLEMENTATION_DESIGN.md) and [native partial/mixed-context findings](PULL_INLINE_WRITE_NATIVE_QUALIFICATION.md) specify those next packets; this read adds no writer or migration.

```sh
./bin/golf pr diff OWNER/REPO NUMBER \
  --repo-id REPOSITORY_ID --pull-id PULL_REQUEST_ID \
  --base FULL_BASE_TIP_SHA --head FULL_HEAD_SHA
```

MCP `golf_pr_diff` requires `repository`, `number`, `repository_id`, `pull_request_id`, `base_commit_id` and `head_commit_id`. Canonical bindings are validated before a temporary PAT login; successful CLI output follows session logout. Bearer mode uses its separately scoped credential and current source authority. The catalogue has23 tools. This exposes reading, not agent approval/publication authority.
