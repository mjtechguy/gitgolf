# PR changed files and shared diff workspace

`RepositoryService/GetPullRequestDiff` accepts the target repository, PR number and the complete lowercase base/head commit IDs selected from PR detail. The native PR must match that selection before and after the bounded `.diff` read. PR ID and head/base repository identity are also compared after the read. The existing repository/session boundary rechecks identity and access after provider waits; responses use `no-store`. Browser sessions and explicitly allowlisted read-only Golf API credentials can call the procedure using their native repository permissions.

Output is native UTF-8 PR merge-base diff, at most512KiB with an exact byte count. Larger, malformed encoding/control, unexpected content-type/status or inaccessible output fails without returning partial text. A changed comparison returns `failed_precondition`; refresh PR metadata to select the new comparison. This is a before/after observation, not an atomic native lock, proof of patch completeness or trusted merge authorization. In particular it cannot eliminate a native ABA change or prove the provider's internal cache identity. The endpoint supports target-repository PR reads without requiring a same-repository head; actual private-fork base-only read and source-access denial are now qualified by `make qualify-pull-workspace`; this does not establish complete patch integrity or protected publication.

The PR Files changed URL uses `?view=pulls&pull=N&pullView=files`; Conversation remains the default. PR/commit views share a client parser and global diff layout. File navigation/search, collapsed native headers, safe literal source rows, old/new line anchors, unified/split views, rename/delete/binary notices and session-scoped Viewed markers use the selected comparison. Source lines such as `+++ b/another-file` inside a hunk cannot invent a file. Git C-quoted UTF-8 names and zero-length ranges are supported. Invalid hunk counts retain native text rather than fabricating line numbers. More than500 files or12,000 rows in the comparison falls back to native text, retaining the complete bounded output. File Viewed state is private in-memory UI state, resets with comparison/unmount and is not a durable submitted review or approval.

No HTML is executed from paths, code or metadata. Line anchors use comparison IDs plus file index and side/line. Number-only anchors identify that comparison; they are not proof of context outside the patch. Split rows align deletion/addition groups without changing patch content. The full native output remains explicitly expandable. Text/source read limits remain, and complete large-patch virtualization, whitespace comparison, syntax tokens in changed-line rows, inline native threads, drafts, human reviews and merge readiness are still required by GX-3/GX-4/GX-6/GX-8.

Primary native interface: [Gitea PR API](https://docs.gitea.com/api/operations/repo-download-pull-diff/). Resolve against the deployed pinned native version before claiming qualification. Commit comparison semantics remain [root or first parent](COMMIT_DIFF_CONTRACT.md); a PR merge-base diff does not change them.
