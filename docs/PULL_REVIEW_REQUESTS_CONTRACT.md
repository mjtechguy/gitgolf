# Individually requested PR reviewers

Golf exposes current requested users in the PR sidebar. An explicit Add opens the shared TanStack selection form; canceling a request uses a confirmation dialog. The form's candidate list uses the existing native repository assignee inventory. Team reviewers, CODEOWNERS routing and broader reviewer discovery remain separate work.

The portable backend uses supported Forgejo requested-reviewer POST/DELETE endpoints and current PR JSON. It never reads a pending review to infer requested users. A missing inventory, malformed identities, closed/merged PR, archived/disabled pull unit or changed PR/request inventory refuses writes. Native observations do not provide atomic CAS against independent native writers.

A current PR author or exact native pull-unit writer may manage requests. Golf/global administration and code-push permission alone do not substitute for this unit authority; a native site administrator must have ordinary repository delegation unless they authored this PR. Candidate ID/login and current native repository access are checked independently. The UI initially selects from the native repository assignee list; users absent from that list are not offered by this picker.

Migration072 preserves each original request, caller, target, reviewer, desired add/remove and both expected revisions in an immutable Golf PostgreSQL journal. It retains metadata, never a provider credential. Reservation precedes dispatch; authority/identity/revisions are repeated after waits under the existing repository lifecycle lock. An exact permit binds the native method/path/payload to this original operation. Supported native response and requested-user readback must agree before success. Replayed original operations only inspect the journal; changed intent under an existing key refuses.

A native error/lost response remains `DISPATCH_UNKNOWN`, never an automatic resend or inferred success from a later inventory. Unresolved requests exclude other relevant repository writers through the existing lifecycle fence. Current-authority inspection is browser/session-only; current loss of request-management authority masks the original outcome. Closing a PR removes request-management authority in this initial contract, including inspection through this control. This does not prove eligible approvals, protected merges, merge queues or atomic protection enforcement.

Runnable checks:

- `GOLF_TEST_DATABASE_URL=… go test -race ./internal/server -run '^(TestReviewRequest|TestFileMutation)' -count=1` exercises real isolated PostgreSQL and controlled native boundaries, including immutable/replayed/changed originals, unknown writes, stale inventory, unavailable/closed targets and foreign-write exclusion.
- `GOLF_TEST_DATABASE_URL=… python3 scripts/repository-file-writer-native-proof.py --stack-root /path/to/retained/golf-git --output /private/new/output` exercises production HTTP handlers against a retained native installation, with disposable users/repository and isolated test schemas. It passed in an earlier native qualification on a since-retired backend and has not been repeated on Forgejo 15.0.9. No Docker resources are created/restarted/resized. It verifies actual ordinary contributor source edits/protection/revocation and actual reviewer add/remove, exact identities, original inspection/replay and closed-PR refusal. The launcher purges its native fixtures.
- `npm exec -- playwright test tests/pull-review-requests.spec.ts tests/repository-file-changes.spec.ts --workers=1` exercises explicit forms, original-operation handling, reader restrictions, foreign receipts/account transitions and mobile themes. Source-browser fixtures are not served-runtime evidence.

Supported endpoint references: the create/cancel review-request operations in the [pinned Forgejo 15.0.9 Swagger](compatibility/forgejo-15.0.9.swagger.json) and the [upstream implementation](https://codeberg.org/forgejo/forgejo/src/tag/v15.0.9/routers/api/v1/repo/pull_review.go). The actual qualification launcher checks the pinned installed version independently.
