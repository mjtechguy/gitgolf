# Golf implementation status

Updated: 2026-10-02. This ledger records evidence for the [implementation plan](../GOLF_IMPLEMENTATION_PLAN.md). A plan, compiled source and live provider qualification are different evidence levels. Git history identifies the implementation revision containing this ledger.

## Current delivery

The developer preview is implemented: a versioned Connect Go API and typed-route React application backed by separate Golf/Gitea PostgreSQL databases, optional scoped Gitea browser OAuth plus per-user token bootstrap, encrypted persistent sessions with account listing and current/individual/bulk revocation, member-scoped organization/team/member/repository browsing, authorized repository list/create, repository/branch/history/source browsing, read-only issues and PR/native-review browsing, a read-only JSON CLI, black/charcoal/light/system themes, live health checks and Compose/Helm installation. Gitea owns Git and collaboration data; Golf does not write Gitea's database or repository files.

The [repository browser increment](REPOSITORY_BROWSER_CONTRACT.md) resolves branches to immutable commits before traversing folders/files. It previews bounded ordinary UTF-8 text, leaves binary/large/LFS/symlink/submodule content as metadata, and distinguishes empty repositories from provider failures. Browser navigation supports deep links/history and clears private query data on authentication changes. Issue bodies are plain text; issue/comment mutations, rendered Markdown, diffs, blame and PR/review mutations remain future work.

`make cli` builds `bin/golf`. It reads through the same per-user API using an ephemeral bootstrap session, closes the session after each command, and emits the documented `golf.cli.v1` JSON envelope. It has no stored-credential or OAuth/device flow, managed authentication, mutation commands, MCP or ACP. Normal cancellation closes the session; cancellation while reading a token also unblocks stdin. Abrupt process termination remains bounded by server session expiry.

Marketing and docs have independent private repositories: [golf-website](https://github.com/mjtechguy/golf-website) (Astro) and [golf-docs](https://github.com/mjtechguy/golf-docs) (Docusaurus/MDX). Both have static production builds and manual Cloudflare configuration. No live Cloudflare site or product service has been deployed by this work. No repository CI workflows were added.

The [Helm chart](../deploy/helm/golf/README.md) packages the current shared core with existing Secret references, optional bundled PostgreSQL/Gitea, retained PVCs, probes, resource/security bounds, native ingress and network policies. Golf can share sessions across replicas; Gitea retains one canonical writer. See [Kubernetes installation and qualification](KUBERNETES.md).

This is **not complete v1**. Golf local/external OIDC identity, organization/role administration, connections/import, PR/review mutations and protection/merge policy, pipeline execution, agents, Cloudflare resources, email/webhooks and protected deployments remain unimplemented. Gitea capabilities reachable outside Golf are not automatically Golf features.

The two infrastructure tracks remain distinct choices over shared product policy. The portable target runs completely in Docker or Kubernetes and can mix optional Cloudflare backends with other providers. The [competition milestone](COMPETITION_READINESS.md) applies only to the Cloudflare track and requires real Workers, Artifacts and concurrent agents. It is not yet ready.

The real provider check established Gitea's minimum scope combination: code and PR/native-review browsing use `read:user,read:repository`; repository creation uses `write:user,write:repository`; issues additionally use `read:issue`. Gitea 1.27.3 requires both user/repository scopes on the user repository route. UI and setup instructions expose these distinctions; insufficient tokens correctly receive denied operations rather than silently receiving broader credentials.

The Git transport check uses `git push` and `git ls-remote` to compare the exact commit. The previous immediate branch-detail API 500 was reproduced while Gitea's initial-push metadata remained `empty: true`; it became healthy after initialization completed. Golf now checks that metadata before branch enumeration, and the smoke uses a bounded initialization wait. Empty state is explicit; unrelated provider failures still fail visibly. This qualifies the new read operations, not every Gitea API or write policy.

The current contract increment adds deterministic Buf/SQLC drift checks; generated Go and TypeScript clients; typed Connect errors; pre-decode origin/session checks and compressed-input bounds; string IDs/uint64 sizes/optional false visibility; actual TanStack routes; and PostgreSQL tests for session scoping, transactional rollback and migration locking. Native pgx, organization policy and broader schema remain open.

Optional browser OAuth is configured through a registered confidential Gitea application; the normal local stack remains OAuth-unconfigured after disposable tests. The public options RPC and UI gate this flow on configuration and qualified dependencies. Login/source UI screenshots retain black/charcoal/light/mobile checks, and source browsing is now a deferred bundle.

Kubernetes qualification used an isolated cluster and private explicit kubeconfig; the user's `k3d-victor-kv` context and existing Compose/site services were unchanged. The denied-client probe initially failed because BusyBox's short-name lookup did not resolve the service; full Kubernetes DNS names fixed the harness. The successful run tested actual network denial, not port-forward behavior. All temporary credentials/users/repositories/releases/namespaces were removed; the dedicated cluster was removed afterward. Helm uninstall retention was asserted before destructive disposable-namespace cleanup.

The identity increment adds real PostgreSQL evidence for state/binding/expiry/replay, PAT replacement and immutable identity linkage, cross-replica refresh serialization, transient provider and identity lookup failures, invalid grants, oversized/redirecting responses, wrong identities, update rollback, absolute expiry during row-lock waits and provider exchanges, and old-schema PAT-preserving migration. A downgrade explicitly invalidates OAuth sessions. Provider rotation cannot be rolled back if the subsequent database commit fails; that path fails closed and may require sign-in.

The [session management increment](SESSION_MANAGEMENT.md) uses non-credential decimal IDs and identity-first transactional locks; existing PAT/OAuth cookies and absolute expiry survive its additive migration. Actual PAT and OAuth controls were exercised, including saved-cookie replay rejection and concurrent bulk revocation. This does not revoke provider credentials or cancel already-authorized in-flight requests.

The [isolated Gitea role qualification](GITEA_IDENTITY_ROLE_QUALIFICATION.md) proves per-unit Git/API grants and additive membership revocation. It also establishes that issue-read permits reporting/commenting, repository admin permits deletion, and member-count guards do not guarantee a recoverable owner. Golf roles are not implemented. Exact capability decisions and enforceable alternate-path restrictions remain gates before role administration.

The [organization browser](ORGANIZATION_BROWSER_CONTRACT.md) exposes current native memberships and provider-visible teams with typed routes and six generated read operations. It checks actual self-membership before/after provider reads, immutable caller identity, team-to-organization binding and local session validity after waits. Private views are removed on denial. It adds no second membership database or editable Golf roles; missing organization scope on an existing grant requires provider grant revocation followed by new explicit consent. Empty provider pages can still have a next page.

The [PR read increment](PULL_REQUEST_READ_CONTRACT.md) adds generated list/detail/native-review procedures, typed browser navigation and `pr list/view/reviews` CLI reads. List heads are always retained snapshots; detail refs can be provider observations or retained fallbacks after source deletion. Review states, reviewed commits and stale/dismissed/official flags remain native records. The real check demonstrates authorized private-fork metadata without blanket fork access and explicit pagination through a hidden pending-review page. The expanded run also verifies real open/closed/all filters, page termination and missing-repository-scope denial across all three procedures. Repository identity/access and local session validity are rechecked after provider waits; those checks do not atomically reserve source or review state. No Golf approval eligibility or protected publication is inferred.

The [protected-write investigation](GITEA_PROTECTED_WRITE_QUALIFICATION.md) establishes a concrete remaining P0.8 gate. Gitea's native merge API has no caller expected-base predicate; immediate merges can race asynchronous stale-review dismissal, and native status contexts accept a code writer's assertions. Tested exclusive merge accounts and explicit Git base leases are foundations, not a complete exact-head/base/candidate/approval/fencing solution. The plan now links this evidence without relaxing its requirements. [Proposed ADR 0004](decisions/0004-protected-integration-enforcement.md) specifies the managed mutation boundary and fault qualification required before selection. The local Git atomic-ref proof passes: an unchanged source ref is omitted from wire update commands and cannot provide a verify-only source lock. The [publisher fault qualification](GITEA_PUBLISHER_QUALIFICATION.md) establishes supported exact-C push/manual bookkeeping and reproduces provider-accepted old-authority writes, private-fork source races and deleted-source snapshot fallback. Its uncertainty journal is experimental and does not enforce H/P/A/E/F. The [mutation inventory](GITEA_MUTATION_BOUNDARY_INVENTORY.md) identifies current unmediated ports/ingress, credential paths, OAuth exceptions and provider/background operations, including reads that initiate checks. It is explicitly static; this does not qualify a managed publisher or close P0.8.

## Initial decisions and limits

See [ADR 0001](decisions/0001-initial-forge-and-vertical-slice.md). The bootstrap REST/native-history exceptions are retired by [ADR 0002](decisions/0002-generated-api-and-typed-navigation.md): existing operations use generated Connect contracts, SQLC queries and TanStack Router. Wider service schemas, identity and tenant policy remain future work. AES-GCM protects the stored upstream credential using the configured key, with authenticated session binding. Rotation, external secret stores and FIPS are not claimed. Browser authentication now supports a configured Gitea authorization-code/S256-PKCE application, with explicit scoped consent, single-use PostgreSQL state/browser binding and encrypted rotating credentials; token bootstrap remains. See [ADR 0003](decisions/0003-gitea-oauth-and-session-refresh.md). This is not Golf local accounts, generic external OIDC, CLI managed authentication or complete account lifecycle.

Local HTTP requires explicit loopback-only insecure-cookie configuration. Remote deployment requires HTTPS. Credentials stay server-side, cookies are HttpOnly/SameSite, all RPC requests require the exact configured Origin before decoding, and authenticated upstream redirects are refused. These controls and tests do not constitute a full security audit.

Compose and Helm use separate database roles, non-root runtimes and persistent PostgreSQL/Gitea volumes. The Kubernetes chart shares the byte-identical initialization script and supports operator-managed external dependencies. Backups, production TLS/controller integration, version upgrades, node/storage fencing and a recovery runbook still need qualification. StatefulSet identity and RWO claims do not establish partition fencing; manually forced stateful replacement is not supported by this evidence. Gitea Actions is disabled; implementing Golf pipeline ingestion later does not authorize adding CI to this repository now.

## Next work and release gates

1. Advance identity/tenant foundations and resolve the guide register’s pending ADRs and Gitea protected-write/conditional-merge qualification before adding protected collaboration writes. The read-only browser/CLI extension does not close those gates. Use the recorded stale-approval, trusted-check-author and missing expected-base evidence to select and qualify a supported complete enforcement design; do not assume a queue lock or UI check resolves it. Never enforce a Golf restriction solely in the UI while other Gitea writes bypass it.
2. For the **Cloudflare competition track**, pull forward the smallest real Worker/Artifacts task flow: scoped forks, two overlapping supported agents, cancellation, exact-commit test evidence, comparison and conflict-aware integration. Follow the [requirements/evidence matrix](COMPETITION_READINESS.md); a static website or provider logo is not proof.
3. For the **portable track**, extend the verified core Kubernetes packaging with qualified local/customer execution. Keep all required core behavior usable without Cloudflare or inference; optional backends can be selected individually.
4. Qualify Actions/GitLab engine subsets and five harness/auth combinations using actual positive/negative lifecycle checks. No adapter placeholders may report ready.
5. Add protected previews/CD, email/webhooks, observability and recovery as real independently verified behavior. Preserve exact source/output identity and deny unauthorized promotion.
6. Complete the two-track installation, migration, no-AI, security/retention, backup/restore, upgrade and load/cost gates before claiming v1, scale or superiority.

Provider credentials, domains, account entitlements, production resources and Kubernetes access are not assumed. Later work can proceed independently until a concrete provider proof needs those inputs; record unavailable capabilities accurately.
