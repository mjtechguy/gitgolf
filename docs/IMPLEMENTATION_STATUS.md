# Golf implementation status

Updated: 2026-10-02. This ledger records evidence for the [implementation plan](../GOLF_IMPLEMENTATION_PLAN.md). A plan, compiled source and live provider qualification are different evidence levels. Git history identifies the implementation revision containing this ledger.

## Current delivery

The developer preview is implemented: a versioned Connect Go API and typed-route React application backed by separate Golf/Gitea PostgreSQL databases, optional scoped Gitea browser OAuth plus per-user token bootstrap, encrypted persistent sessions with account listing and current/individual/bulk revocation and own-account session activity, member-scoped organization/team/member/repository browsing, authorized repository listing and durable own-account creation, repository/branch/history/source and native commit-diff browsing, read-only issues and PR/native-review browsing, owner-issued source-session-bound read-only API credentials, a read-only JSON CLI, black/charcoal/light/system themes, live health checks and Compose/Helm installation. Gitea owns Git and collaboration data; Golf application features do not write Gitea's database or repository files. The explicitly scoped offline recovery operator uses native database/volume restoration into a fresh stopped target, as described below.

The [repository browser increment](REPOSITORY_BROWSER_CONTRACT.md) resolves branches to immutable commits before traversing folders/files. It previews bounded ordinary UTF-8 text, leaves binary/large/LFS/symlink/submodule content as metadata, and distinguishes empty repositories from provider failures. Browser navigation supports deep links/history and clears private query data on authentication changes. Issue bodies are plain text; issue/comment mutations, rendered Markdown, PR comparisons, blame and PR/review mutations remain future work.

`make cli` builds `bin/golf`. PAT mode reads through the same per-user API using an ephemeral bootstrap session and closes the session after each command; API credential mode delegates its issuing session without login/logout or a cookie jar, and emits the documented `golf.cli.v1` JSON envelope. The new [local MCP adapter](MCP_CONTRACT.md) exposes the same 19 reads with `golf.mcp.v1` results and a fixed owner-configured origin and API credential or PAT; native-provider/SDK-client and separate raw-wire cancellation qualification pass. It has no managed stored-credential or OAuth/device flow, managed authentication, mutation commands, remote MCP or ACP. Normal CLI cancellation closes the session; cancellation while reading a token also unblocks stdin. Abrupt process termination remains bounded by server session expiry.

Marketing and docs have independent private repositories: [golf-website](https://github.com/mjtechguy/golf-website) (Astro) and [golf-docs](https://github.com/mjtechguy/golf-docs) (Docusaurus/MDX). Both have static production builds and manual Cloudflare configuration. No live Cloudflare site or product service has been deployed by this work. No repository CI workflows were added.

The [Helm chart](../deploy/helm/golf/README.md) packages the current shared core with existing Secret references, optional bundled PostgreSQL/Gitea, retained PVCs, probes, resource/security bounds, native ingress and network policies. Golf can share sessions across replicas; Gitea retains one canonical writer. See [Kubernetes installation and qualification](KUBERNETES.md).

This is **not complete v1**. Golf local/external OIDC identity, organization/role administration, connections/import, PR/review mutations and protection/merge policy, pipeline execution, agents, Cloudflare resources, email/webhooks and protected deployments remain unimplemented. Gitea capabilities reachable outside Golf are not automatically Golf features.

The two infrastructure tracks remain distinct choices over shared product policy. The portable target runs completely in Docker or Kubernetes and can mix optional Cloudflare backends with other providers. The [competition milestone](COMPETITION_READINESS.md) applies only to the Cloudflare track and requires real Workers, Artifacts and concurrent agents. It is not yet ready.

## Read-only API credential boundary

The [credential contract](API_CREDENTIAL_CONTRACT.md) adds cookie-only owner issue/list/revoke, once-only secrets stored as digests, immutable source-session/owner/forge bindings and separate append-only lifecycle events. Requested expiry is capped by the original session; explicit revocation, expiry or termination of that session denies reads. The exact current 19 CLI/MCP reads plus identity inspection are allowlisted; writes, authentication, lifecycle management and unreviewed future procedures remain denied. Delegated reads recheck native identity and local authority before encoding a successful result. CLI/MCP can use the delegated token without obtaining an upstream secret or opening temporary sessions.

The new schema005 recovery drill passes on image `sha256:4dbc64b946d0de111cf8abf1c923c197dc5ebc46e0c207b39452883846af8632`: metadata/events remain byte-equivalent after restore, both previously revoked and unrevoked old tokens stay denied after fresh same-user sign-in, and a fresh token works after an ordinary whole-stack restart. Final real-PostgreSQL race tests pass (server38.676s/database19.931s); 86 browser fixture checks, both-mode raw MCP cancellation checks, generated-output drift, product checks and Helm qualification pass. Final native CLI/MCP qualification passes on that exact image: all 19 tools in PAT/bearer modes under both protocol revisions, CLI stdin/environment reads, no bearer session/activity additions, cancellation/SIGTERM and explicit/source/native revocation. Production browser qualification passes on the final image: real issue/copy/dismiss, expiry clamp, bearer read/write/manage denial, explicit revoke, actual issuance acknowledgment loss without resend, 21-row pagination/plaintext labels, charcoal desktop/light390px mobile and source-revocation cleanup. All native disposable containers/volumes/networks/private configuration were independently removed. This is part of P1.8/P5.5, not long-lived service accounts, configurable scopes, tenant policy, OAuth/device login, remote MCP, ACP or agent execution.

## Commit-diff read boundary

The [commit-diff contract](COMMIT_DIFF_CONTRACT.md) adds one exact-object read with native root/first-parent metadata and bounded raw provider text. Generated API, CLI, typed browser navigation and native-provider proof are verified for this bounded workflow. The 512 KiB text boundary rejects oversize, invalid UTF-8 and controls instead of truncating locally, while provider output remains unverified for patch completeness or merge eligibility. Existing protection/merge gates remain open.

## Local MCP boundary

The [stdio MCP contract](MCP_CONTRACT.md) adds discovery and 19 named tools over existing CLI/API reads, using official Go SDK v1.8.0 and the two explicitly selected protocol versions. The process owner fixes the origin and exactly one source-session-bound API credential or scoped PAT; tool arguments cannot select credentials, destinations, methods or shell commands. PAT per-call temporary sessions preserve native access checks and add login/logout activity; API credential mode uses its existing session without login/logout, so discovery does not advertise side-effect-free or idempotent behavior. Bounded inputs, four active calls, deadlines and independent cleanup constrain this local adapter. Native-provider/SDK-client checks and separate raw-wire cancellation/framing checks pass. The latter reproduced the unmodified SDK's post-cancel reply and verifies Golf's bounded active-ID guard. No complete protocol-conformance, agent-client execution, remote MCP authorization, ACP, mutation approval or general task lifecycle is qualified by this increment.

## Repository-creation boundary

The [durable creation contract](REPOSITORY_CREATION_CONTRACT.md) is implemented and qualified for the supported personal Gitea create route. A canonical UUID v4 binds exact input to an immutable Golf account/forge; reservation and its initial event commit before the sole permitted provider POST. Replays return recorded evidence without redispatch, including after restart. Keyed callers distinguish `SUCCEEDED`, `REJECTED` and `OUTCOME_UNKNOWN`; unkeyed callers preserve earlier failure behavior but cannot deduplicate separate invocations. Successful metadata requires a current native read of the original repository ID; access loss, deletion or same-name replacement grants no cached access.

Actual browser acknowledgment loss recovers by status-only lookup after reload. A separate native fault proxy discarded Gitea's real HTTP 201 and counted exactly one POST across retries and backend restart; Golf stayed unknown and did not adopt the repository by name. Current caller/foreign-account checks, rollback/concurrency tests and restored operation/event preservation pass. Browser convenience storage uses origin plus native Gitea user ID, not the internal Golf account ID. This is one operation-specific journal, not a general outbox, job engine, organization/tenant model, exactly-once contract or protected-write implementation.

## Credential keyring boundary

The [credential keyring](CREDENTIAL_KEYRING.md) is implemented under [ADR 0005](decisions/0005-credential-keyring-and-drained-rotation.md); final real-PostgreSQL regression and old-binary PAT/pending-verifier checks pass; live OAuth exchange across a key change remains unqualified. It adds labeled PAT/OAuth session and pending-verifier ciphertext, permanent label/material bindings, active-policy fencing and server-operator status/activation/bounded-rotation/retirement commands. Status can run migrations and scan/register legacy metadata. Activation requires draining all old writers, including external OAuth exchanges; database fencing cannot undo provider rotation. Retirement requires zero stored uses in both tables, including expired rows, and erases no secret. This does not qualify rolling key cutover, live OAuth exchange across restoration, KMS/age migration, a FIPS profile or completed P1.3. The separate bounded Docker recovery proof below preserves key configuration/metadata and invalidates every restored application credential. The ledger distinguishes this foundation from broader operational qualification.

## Recovery boundary

The [offline recovery workflow](RECOVERY.md) is implemented for the canonical three-service Docker profile with PostgreSQL 18.4, Gitea 1.27.3 and Golf schema 202610020005. It captures resolved runtime credentials, both native databases and complete Gitea volumes into an age-encrypted operator backup; validates bounded archive/configuration paths and hashes; requires a fresh target and exact locally available image IDs; and restores with both applications stopped. Images are not included. The restore runs a transactional all-session/all-PKCE invalidation and writes independent append-only operator history while preserving identities/account/crypto history, repository-creation operations/events and key metadata. Real PostgreSQL safeguards, offline archive tests and **the complete native backup/restore drill pass**, including simultaneous restart of the restored three-service stack and disposable-resource cleanup.

All writers must be drained. The assertion and read checks do not fence administrators or future writes; restored provider revocations, memberships/protections, deletion tombstones, external OAuth rotation and outbound mirrors/queues require authoritative reconciliation before traffic opens. The pending-verifier fixture is not a live OAuth recovery proof. Kubernetes/external storage, broad inventory/scale, cross-version recovery and production RPO/RTO remain open. This is bounded P1.6 progress, not completion or automatic disaster recovery.

The final native drill verifies data restoration, credential invalidation, signed Git/hydrated LFS/attachments/protection/SSH identity, post-restore writes and simultaneous whole-stack restart. Database startup retries only connection readiness before migrations, every 250ms within the caller deadline (60s when absent), including DNS not-found as well as temporary DNS/transport failures and PostgreSQL startup/connection-slot errors. This handles Docker temporarily withdrawing PostgreSQL's service record during restart. A valid-looking typo in a hostname therefore waits for that deadline; malformed DSNs, authentication/missing-database failures and migrations are not retried. Targeted tests reproduce delayed DNS before real PostgreSQL connection/migration, bounded missing-DNS cancellation/deadlines, immediate native authentication/missing-database rejection and single-execution migration failure. The final rebuilt-image drill and full race regression both pass.

## Observability boundary

The [shared-core observability contract](OBSERVABILITY.md) adds injected zerolog completion logs, optional OTLP/HTTP API/provider/PostgreSQL traces and a separately authenticated private Prometheus listener. The real database/sql pgx connection receives the composite query tracer; operator/test pools preserve their uninstrumented path. No global logger/provider/registry is installed. Fixed methods/routes/statuses and SQL verbs bound exported labels; source/credential/identity/SQL contents and raw panic/provider/exporter errors are excluded.

The optional six-service development overlay adds Jaeger/Prometheus/Grafana and provisioned dashboards while the ordinary three-service profile remains unchanged. [ADR-0006](decisions/0006-private-observability-runtime.md) retains the original guide's Tempo/Loki/log-search requirement as an explicit remaining gap. Export is sampled and best effort: failed attempted batches have a counter/fixed diagnostic, but bounded queue overflow is not included in that counter. Jobs/runners, production SLOs/load/retention/alerting, incoming cross-service propagation and live Kubernetes collector/scraper qualification remain open. This is P1.7 progress, not task completion or durable audit evidence.

The real provider check established Gitea's minimum scope combination: code and PR/native-review browsing use `read:user,read:repository`; repository creation uses `write:user,write:repository`; issues additionally use `read:issue`. Gitea 1.27.3 requires both user/repository scopes on the user repository route. UI and setup instructions expose these distinctions; insufficient tokens correctly receive denied operations rather than silently receiving broader credentials.

The Git transport check uses `git push` and `git ls-remote` to compare the exact commit. The previous immediate branch-detail API 500 was reproduced while Gitea's initial-push metadata remained `empty: true`; it became healthy after initialization completed. Golf now checks that metadata before branch enumeration, and the smoke uses a bounded initialization wait. Empty state is explicit; unrelated provider failures still fail visibly. This qualifies the new read operations, not every Gitea API or write policy.

## Initial decisions and limits

See [ADR 0001](decisions/0001-initial-forge-and-vertical-slice.md). The bootstrap REST/native-history exceptions are retired by [ADR 0002](decisions/0002-generated-api-and-typed-navigation.md): existing operations use generated Connect contracts, SQLC queries and TanStack Router. Wider service schemas, identity and tenant policy remain future work. AES-GCM protects the stored upstream credential using the configured key, with authenticated session binding. The keyring increment above adds a qualified bounded rotation workflow; live OAuth exchange across activation or restore, production/Kubernetes cutover, broader recovery topologies, external secret stores and FIPS remain unqualified. The bounded Docker backup/restore proof above restores key configuration/metadata and invalidates application credentials before reopening. Browser authentication now supports a configured Gitea authorization-code/S256-PKCE application, with explicit scoped consent, single-use PostgreSQL state/browser binding and encrypted rotating credentials; token bootstrap remains. See [ADR 0003](decisions/0003-gitea-oauth-and-session-refresh.md). This is not Golf local accounts, generic external OIDC, CLI managed authentication or complete account lifecycle.

Local HTTP requires explicit loopback-only insecure-cookie configuration. Remote deployment requires HTTPS. Credentials stay server-side, cookies are HttpOnly/SameSite, all RPC requests require the exact configured Origin before decoding, and authenticated upstream redirects are refused. These controls and tests do not constitute a full security audit.

Compose and Helm use separate database roles, non-root runtimes and persistent PostgreSQL/Gitea volumes. The Kubernetes chart shares the byte-identical initialization script and supports operator-managed external dependencies. The bounded Docker recovery runbook, PostgreSQL safeguards and full native fresh-restore/whole-stack restart drill pass. Kubernetes recovery, production TLS/controller integration, version upgrades and node/storage fencing still need qualification. StatefulSet identity and RWO claims do not establish partition fencing; manually forced stateful replacement is not supported by this evidence. Gitea Actions is disabled; implementing Golf pipeline ingestion later does not authorize adding CI to this repository now.
