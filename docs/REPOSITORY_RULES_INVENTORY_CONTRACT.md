# Repository rules: current read inventory

This source packet implements a managed-browser reader and a concrete shared-table component for current branch protection, tag protection and native merge configuration. It performs no native writes, adds no schema migration and grants no CLI/MCP/API bearer access. Root integration and actual served/native qualification remain required. The Rules section becomes **Partial**, not Ready, only after the reader is mounted and qualified.

## Supported native observations

Pinned Gitea1.27.3 exposes whole protection arrays through `GET /repos/{owner}/{repo}/branch_protections` and `GET /repos/{owner}/{repo}/tag_protections`. Both routes require a native token and repository admin. They do not implement paginated list parameters or a count receipt. Golf therefore reads the actual whole arrays and never invents pages or treats a filtered branch list as a protection inventory. See the pinned [branch list handler](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/api/v1/repo/branch.go#L553), [tag list handler](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/api/v1/repo/tag.go#L282) and [router authority](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/api/v1/api.go#L1223).

Branch observations retain the native rule pattern, signed64 priority, nonnegative signed64 required approvals, check contexts, push/force-push/merge/bypass/approval account and team lists, deploy-key switches, review/staleness/signing/admin-override switches, file patterns and timestamps. Native branch protection conversion supplies a rule name rather than a numeric protection ID; Golf uses the exact pattern as that inventory row identity. Tag observations retain the positive signed64 native protection ID, pattern, allowlists and timestamps. These are configured rules, not a Golf-computed effective match or ordered enforcement decision. See the pinned [branch schema](https://github.com/go-gitea/gitea/blob/v1.27.3/modules/structs/repo_branch.go#L29) and [tag schema](https://github.com/go-gitea/gitea/blob/v1.27.3/modules/structs/repo_tag.go#L57).

Repository metadata supplies the merge/rebase/explicit-rebase-merge/squash/fast-forward/manual/update choices, automatic manual-merge detection and deletion/maintainer-edit defaults, plus default merge/update styles. Golf exposes the observed booleans independently; it does not infer that the default style is permitted, that a pull request is mergeable or that the caller may merge. Disabled pull-request units can still expose native default configuration. See the pinned [repository schema](https://github.com/go-gitea/gitea/blob/v1.27.3/modules/structs/repo.go#L105) and [repository conversion](https://github.com/go-gitea/gitea/blob/v1.27.3/services/convert/repository.go#L89).

## Exact target and private read boundary

`RepositoryRulesService.GetRepositoryRules` accepts the exact repository key, canonical positive native repository and owner IDs, and the current Access revision. It requires a managed browser cookie and configured Origin; delegated/API bearer headers are denied. Managed OAuth or native-token browser sessions are not excluded merely for lacking a Golf password account.

The reader observes native repository admin and positive individual authority before and after its payload reads. Personal ownership or current direct-admin membership is supported. Organization authority requires current membership and independently observed organization ownership or direct-admin membership. Golf global administration, exceptional native site-admin ownership and indirect team-admin permission alone do not authorize this private inventory. Hidden/unknown native observations fail closed. Archived and mirrored repository configurations remain readable; no edit authority follows from the observation.

Both native arrays and merge metadata are read twice. Exact typed response equality detects observed payload drift; the final authority observation binds repository/owner IDs, owner kind and access revision. A returned rules revision is an opaque observation fingerprint. It is not native CAS, a lock, an atomic cross-endpoint snapshot, absence of ABA changes, native write attribution or evidence that a rule remains unchanged after the read. An upstream denial is an error, never an empty successful inventory.

Bounds are100 branch rules and100 tag rules,100 strings per list,512 UTF8 bytes per nonempty name/list entry,4096 per file-pattern string,64 per timestamp, existing2MiB native transport,1MiB projected protojson and one15-second overall request deadline. Native boolean/integer/style fields must be present; malformed flags are not silently false. Duplicate branch names, tag IDs or tag patterns are refused. Duplicate list values, if supplied by the provider, are preserved. Complete empty native arrays render honest empty sections. No truncated subset is returned on a bound or validation failure.

## UI and root seams

`RepositoryRules({client,userId,owner,name,access,signingOut,revalidating})` takes a generated `Client<typeof RepositoryRulesService>` and the verified current Access observation. Root owns central service/client/route wiring:

1. Register the generated service handler and managed-browser pre-decode procedure. Do not add an API bearer grant.
2. Create the generated client through the existing shared transport. Mount the component under `/OWNER/REPO/settings/rules` and the common repository settings layout. Do not infer inspection availability solely from `Access.canManage`, which deliberately excludes archived/mirror writes; the new reader independently checks current native read authority.
3. Keep previous authority metadata hidden/inert during parent revalidation. Actual denial, user/account change or target replacement must unmount the panel or supply the changed target. The component aborts/removes its private query on those changes and independently hides rows and details during its own refresh/error/signout.
4. Update coverage to Partial with a link to this contract; rule editing/enforcement remains open. Root merges the additive descriptors and runs managed-PG/native/served checks before recording verification.

The component uses global panel/dialog classes and shared TanStack DataTables, including common loaded-entry search, sorting and pagination. Signed64 priority/approval sorting uses BigInt without precision loss. Rule details open only on explicit icon buttons; the read-only item dialog uses the shared detail grid, close focus and native Escape handling. There are no forms, Add/Edit actions, matching previews, merge buttons, persistent private payloads or new CSS rules. Merge choices are explicit Enabled/Disabled observations; configuration is not relabelled as runtime enforcement.

## Prepared actual qualifier (not executed)

`scripts/repository-rules-smoke.py --image <cached-revision-labelled-Golf-image> --output <new-private-directory> --ui` creates a fresh base Compose project, with CI/agents unconfigured. It never builds/pulls or changes the retained deployment. The image and pinned native version are independently observed before/after. An existing local Playwright installation is required for the optional browser proof. Python `--self-check` and the browser helper's `--self-check` validate the frozen wire, exact whole receipts, signed64 preservation, missing-field refusal and original-failure preservation without Docker, HTTP or browser execution.

The prepared fixture uses seven non-site-admin native actors (owner, direct admin, organization member/direct admin, team-only admin, reader, Golf global admin and outsider). Supported native APIs configure two branch patterns, two tag patterns, actual allowlists and mixed merge defaults. Golf whole arrays, every projected flag/list/pattern/time/ID and native merge settings are compared independently. The fixture also covers actual archived and owned Git-mirror reads, changed inventory revisions, serial native role loss, wrong IDs/access revision, native rename/replacement, Origin/bearer/logout denial. The mirror uses only its fresh native service's own Git endpoint; the isolated migration host allowance is restricted to `gitea`. No native site-admin bypass or managed OAuth runtime qualification follows from this fixture.

The optional browser visits the canonical Rules URL and captures inventory, explicitly opened item details and reload for both themes at1440/390 (12 captures). It verifies exact RPC request/whole receipt, no-store, actual theme/font loading and document overflow, and blocks unexpected browser mutations. Credentials only enter private stdin and are never written to manifests/captures. Safe manifests bind runtime identity, failure stage and owned cleanup. Native repository/org/user cleanup uses exact current IDs without credential redirects; managed accounts are disabled and sessions/bearers revoked, then the fresh project's containers/volumes/network are removed. Failed evidence is retained rather than overwritten.

This is a **prepared** qualification recipe: no native or served result is claimed until root executes it. Serial movement/revocation proves current refusal after the change, not a byte-boundary in-flight race or an atomic read. Managed-PG tests cover injected between-read drift/final revocation/replacement separately; neither substitutes for P0.8 enforcement.
