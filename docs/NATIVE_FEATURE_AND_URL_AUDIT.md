# Native feature and URL audit

Reviewed 2026-10-03 against the baseline and Golf URL/unit source `bfbb5deba7d86c298cc18b81e9326b402da9d533` and the then-installed native forge, which used the since-retired backend; the review has not been repeated on Forgejo 15.0.9. Both infrastructure tracks retain the same supported native API/Git boundary. This is an implementation inventory, not full parity qualification.

## Native integration

Golf's custom UI calls its own typed API; `internal/server/forge.go` translates to supported `/api/v1` requests using the current caller's provider credential. Exact-target reads independently recheck native identity and current permissions. Native Git handles repository objects and transport; Golf owns sessions, journals, private drafts, policies and agent orchestration. The inspected product adapters do not write the native database or canonical repository files directly. Follow the [pinned native API router](https://codeberg.org/forgejo/forgejo/src/tag/v15.0.9/routers/api/v1/api.go) and installed OpenAPI when adding features, rather than assuming the latest documentation matches this installation.

| Area | Current integration | Remaining product coverage |
| --- | --- | --- |
| Source | Repository creation, source/history, branches/tags, commit/PR comparisons, Git clone/fetch/push through native transports | File editing/upload, branch/tag mutations, blame, richer search and fork/import/mirror UI |
| Collaboration | Issues/PRs, comments and lifecycle, overall human reviews, bounded inline reads; encrypted Golf private drafts with bounded explicit saved-version native publication | Complete inline publication lifecycle/native pending drafts, replies/resolve, dismissal, suggestions, reviewers/CODEOWNERS, labels/assignees/milestones/reactions |
| Administration | Own SSH keys/profile, general repository settings, collaborators, organization/team reads and bounded membership edits | Full organization/role lifecycle, transfer/archive/delete, unified suspension and Git credential ingress |
| Native capabilities | Supported adapter reads/writes above | Releases/assets, notifications/watch/star, Wiki, packages and remaining native features need deliberate adapters/UI and tests |
| CI | Native Actions deliberately disabled; Golf's own bounded shell engine | Maintained GitHub/GitLab workflow execution, multi-job/actions/matrices/services/reusable workflows, artifact/secret/provenance and executor parity |

The unit-navigation gap now has a bounded source implementation: optional repository configuration fields preserve explicit false versus unknown. Explicitly disabled Issues/PR units hide their tabs and prevent the corresponding work panels from mounting or issuing feature reads, including deep links and Compare. Mutable activity revalidates repository metadata without moving source/comparison snapshots. True remains configuration, not current authority or evidence of an internal unit: installed native `has_issues` and `has_wiki` also cover external units. Golf does not follow their arbitrary URLs. Wiki configuration is visible read only; no usable Wiki editor/workspace is implied. Golf passwords and `golf_ro_` API credentials are not native HTTP Git credentials. SSH keys normally remain independent of browser logout/password changes, but disabling a Golf account must eventually enforce the intended suspension across native Git/API ingress as well. See [Git access contract](GIT_ACCESS_CONTRACT.md). Protected merge and bypass/write-path enforcement remain the P0.8 release gate.

## URL contract

Golf already uses familiar `/OWNER/REPO`, `/issues/N`, `/pull/N/files`, `/commit/SHA` and `/actions/runs/ID` shapes. The native forge does not impose the custom browser URLs. Its API and Git transport URLs are separate interfaces.

Current source links are immutable `tree/SHA/path` or `blob/SHA/path`; branch/tag names are query context, not proof that a ref still points to the selected SHA. This avoids ambiguity between slash-containing refs and paths. GitHub supports both ordinary branch/ref URLs and immutable SHA permalinks; see [GitHub permanent-link documentation](https://docs.github.com/en/repositories/working-with-files/using-files/getting-permanent-links-to-files).

Implemented and locally deployed in the latest bounded increment (339 affected browser cases plus actual served/native proof; qualification details in implementation status):

1. Strip redundant `ref` when source/path-history routes encode the SHA and omit path-owned view/detail query selectors. Keep deliberate source/history return context on other work pages and list filters only on Issues/PR views.
2. Provide canonical `/OWNER/REPO/settings` and supported settings subpaths, retaining old `/repositories/...` aliases.
3. Normalize legacy source links even when their selected SHA is unchanged; distinguish directories (`tree`) from files (`blob`) using authoritative returned kind.
4. Apply shared deep-selector validation to canonical and legacy deep links.

Still required: add readable branch/tag browsing URLs through an explicit resolver that handles slash refs, branch/tag name collisions, literal paths, renamed repositories and current authority. Retain the readable address while resolving to an exact snapshot for API/agent/review operations; keep a separate Copy permalink action. Do not silently resolve ambiguity by guessing. The [readable source URL design](READABLE_SOURCE_URL_DESIGN.md) specifies the exact-source foundation, caller migration, subsequent route implementation and qualification tasks; RS-1 exact-source foundation is now locally deployed and qualified; RS-2 readable routing is still design work.

Source evidence: `web/src/navigation.ts`, `web/src/router.tsx`, `web/src/RepositoryBrowser.tsx`, `web/src/RepositoryRefs.tsx`; supported adapter evidence: `api/golf/v1/golf.proto`, `internal/server/forge.go`, `internal/server/pulls.go`, `internal/server/repository_settings.go`, `internal/server/git_access.go` and `compose.yaml`. Route/ref checks include slash branches, back/forward/reload, exact tag commit selection, settings aliases, malformed selectors, conflicting redundant refs, preserved fragments, file-kind normalization and authority failures. Normalization uses only the authorized returned source kind and current logical route; a stale receipt cannot overwrite a newly selected file or work tab. They do not establish completed readable-ref URL or native feature parity.

The later bounded saved-version human inline publisher now has actual local schema 037 managed-browser/native proof, including three decisions, complete original-context children, known refusal receipts, cross-tab success activity and known-success cookie/status continuity across restart. Its [contract](PULL_INLINE_PUBLICATION_CONTRACT.md) retains full lifecycle/recovery/authority limits. RS-1 repairs the previously recorded `GetContents` identity gap: expected native ID/full object receipts now span browser/README/navigator/image/CLI/MCP reads under current authority. Supported exact tree/blob APIs replace SHA-shadowable `contents-ext`, including sibling workflow-source consumers. Source, supported-native and actual served evidence is recorded in [implementation status](IMPLEMENTATION_STATUS.md); readable branch/tag routing, rename handling and atomic permission/ref fencing remain open.
