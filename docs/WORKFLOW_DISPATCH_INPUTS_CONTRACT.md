# Typed manual workflow inputs

This contract describes the opt-in `golf.workflow.act.v0.2.89.linux.v2` manual-input catalog, distinct from input-free Actions v1 and the legacy GitLab shell consumer. One owned native/TLS1.3/Docker run qualifies the bounded typed/default/literal/local-composite path on frozen source `33d16cdc4e42fb292747273400a62c49968017a0`. Source and PostgreSQL checks cover additional admission, retention and release boundaries; a later actual read-only served editor/run/scoped-step qualification is recorded below, while every workflow and recovery remain open. The full Actions/GitLab requirements in the [settings packet](REPOSITORY_SETTINGS_IMPLEMENTATION.md) remain applicable, and CI readiness is unchanged.

## Source and parameter semantics

The v2 source consumer admits Actions `workflow_dispatch` string, boolean, number and choice declarations through the maintained engine. Environment selectors remain unsupported until a real environment protection, approval and credential-release consumer exists. GitLab manual variables have distinct precedence and environment-variable semantics; they require a separate consumer.

Parse the exact selected workflow blob, preserving the existing 64-KiB single-document, depth-32, 4096-node, duplicate-key and alias restrictions. A declaration parser does not grant eligibility to the rest of the workflow. Expressions in jobs remain subject to the engine catalog; declarations, descriptions, options and defaults are literal. The current catalog refuses `${{` in descriptions, options and defaults; submitted string parameters may contain that text as inert data. This is a published declaration limit, not recursive evaluation.

Bound declarations/submissions to 25 names, 2048 UTF-8 bytes per string and 8192 bytes per canonical submitted/effective map, within the existing 16-KiB event envelope. Reject unknown or duplicate names, unsupported fields/types, invalid defaults, non-finite or out-of-contract numbers, invalid choices and oversized payloads before admission or credential release. Never trim or evaluate a supplied string. Error text must not contain submitted values.

Refuse declaration names that differ only by ASCII letter case: the pinned evaluator looks up map properties case-insensitively, so two such names would be ambiguous. Submitted names must use the exact declared spelling. This restriction is a published catalog limit rather than a change to the generic expression evaluator.

Presence differs from truthiness: explicit false, zero and an empty string are supplied values. A required omission without a default is refused. The foundation contract uses empty string/false for omitted optional string/boolean values. An omitted optional number or choice without a declared default is refused rather than inventing zero or the first choice. Publish these compatibility limits with the catalog; they are not a blanket GitHub parity claim.

Numbers use finite binary64 semantics and canonical Go JSON representation. Decimal rounding is explicit: for example, `0.10000000000000001` becomes `0.1`, and negative zero becomes `0`. Values outside the safe magnitude bound `2^53-1`, unsafe integral values, non-finite results and nonzero underflow are refused. Numeric wire values are strings; the server independently canonicalizes them. Choices remain strings. Definition ordering and submission ordering must not change their canonical hashes; changes to types, defaults or choices must change the schema digest.

## Immutable admission and original-operation inspection

Typed submissions bind the managed actor, original idempotency key, immutable repository/owner IDs, full commit SHA, workflow path/blob, schema digest and canonical submitted-input digest. The server independently reads/verifies source and computes the effective/defaulted digest. Keep submitted and effective digests distinct.

Preserve the exact legacy input-free intent hash and historical replay behavior. A new versioned typed hash must not reinterpret old rows. Explicit typed mode with an empty map differs from an absent legacy parameter envelope. Same-key changed values, schema, source or native identities conflict instead of creating another run.

Original-key inspection requires the original typed digest and current managed/native authority. It remains read-only, cannot adopt a new digest and never grants retry. Missing original evidence is not proof of no effect. Persist only original identifiers and digests in browser resume metadata; never parameter values. Lost response/reload must not automatically dispatch or inspect.

The additive wire includes exact-source definition metadata and schema digest, submitted values with a typed oneof, immutable target/source fields, and typed run/inspection digests. A present boolean oneof with `false` and a present string oneof with an empty value remain distinguishable from omission. Explicit contract plus submitted/effective digests selects typed mode, including a genuinely empty submitted array; an incomplete typed envelope is refused. The server recomputes values and both map digests before admission. A same-key request that changes its values while reusing the old digest is refused by comparing the decrypted original canonical submitted map, not by trusting the digest claim.

## Preparation consumer

`WorkflowRunService.PrepareWorkflowDispatch` accepts a managed same-origin cookie, immutable repository/owner IDs, a full commit, an Actions workflow path and typed oneof values. It verifies current native writer access before and after exact commit/tree/blob reads, validates declarations and values through the common package, and rechecks the managed session after source reads. Native and Golf actor IDs remain distinct.

The response contains public exact-source declarations, native/source identity and schema/submitted/effective digests. It does not echo submitted values, fetch an archive, plan jobs, reserve a key, upload source, create a run or release credentials. Preparation may succeed while execution is disabled or no maintained engine is installed: its parameter contract is not an execution catalog or admission receipt. Dispatch must independently recompute all bindings, current authority and policy. Preparation neither changes the installation catalog nor enables execution by itself. In the combined UI, Run workflow opens a requested TanStack input form. Preparation precedes one explicit dispatch; only original identity/digest metadata persists before that write. Refresh, account/authority changes and late replies fence the editor. Reload and missing-receipt errors do not resend or silently inspect.

Source test families cover wire presence, defaults, invalid values and outer cookie/Origin/bearer boundaries. Preparation, encrypted retention, admission and release retain their separate PostgreSQL evidence. The runtime proof below covers one real execution; the requested form is source-browser-qualified and now has bounded actual read-only served captures below. Browser dispatch and the remaining privacy transitions remain separate gates.

## Stored values and execution

Submitted/effective maps are immutable authenticated encrypted content under the dedicated `workflow_dispatch_input` domain. Their binding includes run UUID, distinct Golf/native actor IDs, forge/native repository and owner IDs, original key, commit/path/blob, archive/schema/map digests and canonical plaintext size/hash. Neither values nor a copied forge credential enter the plan, audit or notification journal. The retained family participates in startup/missing-key checks, inventory, bounded rotation, retirement, remaining counters and recovery locking in every run state.

Schema059 enforces all-or-none typed run metadata, the v2 manual origin/format, immutable plan/source/input fields, and a deferred exact encrypted-content binding. Existing legacy rows are not adopted. A new typed row and its payload commit together; missing or corrupt content cannot become an executable typed assignment. Any retained pre-admission input rows require coordinated recovery rather than silent migration adoption.

The consumer reopens the admitted archive, verifies its SHA256, finds the exact ordinary workflow file, verifies the Git blob, and independently parses the schema. It checks authenticated submitted/effective maps against that schema and the immutable run digests before claiming/releasing parameters. Current managed session/native writer authority, policy epochs, lifecycle gate, placement/resource generations and attempt/lease state are rechecked. Native permission edits are observations, not an atomic external revocation guarantee.

Only an input-capable worker advertising both v2 and `golf.workflow.dispatch.inputs.v1` over TLS 1.3 may claim typed work. The worker advertises this only after an actually verified coordinator response with certificate chain and hostname validation. The assignment binds `manualInputsContract`/`manualInputsSchemaSha256` in its plan to the `manualInputs` envelope: contract, schema/submitted/effective SHA256 and canonical submitted/effective arrays. Worker validation rejects incomplete or changed bindings before execution; the engine independently reparses exact source/defaults and validates the same maps before Docker effects. Old workers, HTTP consumers and v1 plans receive no typed envelope.

The coordinator constructs canonical Go JSON within 16 KiB. Event `ref` and `after` equal the pinned full commit; `inputs` contains every effective value as a string, including `"true"`/`"false"` and canonical numeric text. Duplicate keys, alternate encodings, missing/extra inputs, non-string event inputs and a changed commit are refused. The maintained evaluator uses declarations to expose typed `inputs` while preserving string-valued `github.event.inputs`. Its narrow number conversion and composite inert-value correction are documented in the [engine contract](ACTIONS_ENGINE.md); neither modifies the module cache or rewrites expressions.

Legacy input-free Actions intent/replay remains v1. Even on a v2-configured instance, a GitHub workflow with zero input declarations uses genuine v1 planning and the original input-free dispatch/inspection shape; undeclared input contexts remain unsupported. The UI selects typed mode only for a nonempty valid declaration inventory. A declared workflow that supplies an empty array to use defaults remains typed, rather than becoming legacy. Legacy GitLab manual execution remains the existing shell path even when the configured maintained-engine catalog is v2; GitLab variables are not reinterpreted as Actions inputs. Push planning/materialization remains v1. Push execution of an input-declaring workflow and v2 repository/organization secret-broker forwarding remain unsupported. Existing broker approvals require v1 and cannot silently execute unapproved v2 source without their values.

Input contexts may be admitted only in existing supported expression positions. Input-driven image selection, resource limits, runner authority, secrets, environment approval or job-graph expansion require separate supported consumers. Other denied platform/provider contexts stay denied. Existing accepted matrix, needs, output and local-composite semantics must remain intact.

Inputs are ordinary workflow parameters, not secrets. Direct users to Secrets settings for credentials. Golf must not imply that arbitrary workflow echo is private or masked. Supplied expression-looking text is data and must never undergo recursive evaluation. Examples pass untrusted values through environment variables instead of interpolating them into shell source.

## Qualification gates

1. Pure declaration/value tests: duplicates, unknown fields, false/zero/empty presence, defaults, required omission, choices, UTF-8, number precision, deterministic digests, schema changes and all byte/count bounds.
2. Real PostgreSQL/race tests: concurrent same-key admission once, changed-intent conflict, legacy replay, encrypted retained values and key lifecycle, wrong actor/native identities, current revocation, capable-worker selection and lost-ack inspection.
3. Pinned engine tests: boolean equality versus string event equality; numeric JSON output versus string event output; job/step/composite input scope; matrix/needs regressions; malicious-looking parameter values remain literal data.
4. Actual owned Docker run: all four types plus defaults/required choices, metacharacters through environment variables, independent source/blob and output receipts, real matrix/needs behavior, invalid values create no run/container, accepted-response loss inspects only the original digest, restart creates no replacement run and native revocation withholds release.
5. Served dark/light desktop/mobile form/detail checks using shared TanStack components and global styles. Parameter entry opens explicitly from Run workflow. Browser storage and diagnostic artifacts must not retain submitted values. Qualification captures may use explicitly disposable synthetic parameter data; they must not expose real private parameters or credentials.

Record frozen product source, exact engine patch/source and binary receipts, actual runtime images, failures and cleanup. Source foundation tests alone do not qualify the public RPC, encrypted storage, execution consumer or deployed UI.
