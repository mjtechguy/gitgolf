# Standard native pull-request merge UI

The source UI supports the bounded `golf.pull.standard-native-merge.v1` contract. Source/browser fixtures are distinct from actual native/served qualification, deployment and schema061 recovery. Full protected merge, Git ingress and Rules requirements remain open.

This bounded slice is deployed on local schema061/component `234d471`. [Actual native/browser qualification](../.tmp/standard-merge061-served-attempt2/qualification/manifest.json) passes explicit writer confirmation, independent output/parent/target readback, original replay/reload/restart with no resend, and reader/protected/fork refusals. [Owned cleanup](../.tmp/standard-merge061-served-attempt2/parent-manifest.json) and [running-component verification](../.tmp/settings-061-running-proof/manifest.json) pass. This does not qualify protected publication, forks, all native transport failures or latest-schema recovery.

**Inspect merge observations** remains an explicit read. Only a freshly validated same-repository, open, ready PR whose named source matches selected full H, whose target is known unprotected, and whose ordinary writer/native caller flags and merge-commit strategy are explicitly allowed can open **Merge pull request**. Unknown/protected targets, forks, changed or unavailable sources, draft/closed/merged PRs and absent permissions remain unavailable. An observation is never an executable permit: the backend independently checks current authority, source and target before its supported native write.

The shared native confirmation dialog describes source branch, target branch and selected H. Cancel receives initial focus; Escape closes without an effect. Confirmation uses the native default title/message. This increment offers only a standard merge commit: no force, auto-merge, branch deletion, rebase or squash. Selected B remains comparison context, not native compare-and-swap protection. Native/external writes are not atomically fenced by these separate reads.

Before one `SubmitStandardPullMerge`, the tab stores only original operation/actor/repository/owner/PR IDs, number, revision, H/B and named refs under an origin/account/repository/PR-scoped key. It stores no merge text, credentials or body. Synchronous guards prevent duplicate submissions. Corrupt or unreadable saved metadata blocks new changes. The backend's durable original intent and exclusion remain authoritative even if browser storage is lost.

Reload performs no mutation or automatic status lookup. **Inspect original merge** calls only `GetStandardPullMergeOperation` with the exact original identity. RESERVED and DISPATCH_UNKNOWN retain uncertainty and block a replacement. Missing receipts, transport errors and malformed receipts do not establish no effect. Only an exact REJECTED/preflight_refused receipt supports an explicitly reviewed fresh selection; a verified SUCCEEDED receipt displays the historical full merge commit. This receipt grants no deployment or protected-merge authority. Original H/B/revision/refs, actor/target IDs, method/contract, phase, timestamps and success-only merge/actual-base hashes are validated before adoption.

The merge component is keyed by actor/repository/PR rather than mutable PR revision, so an own verified inventory refresh preserves the historical receipt. During current-access refresh, private data and controls are hidden; scope/account changes and unmount invalidate pending callbacks. Authority denial clears parent PR data through the existing private-query seam. Original metadata remains inspection-only after uncertain denial. `clearOtherStandardMergeIntents` is exported from the small storage helper for root's global session/logout integration, including logout while the PR component is unmounted. No editor bundle needs to be eagerly imported.

The affected source/browser suite passes 103 cases in 1.3m (new merge, existing observation and PR workspace tests); after the final canonical identity guard, the 29-case merge suite passes 9.1s, including same-tick duplicate confirmation. The 29 existing observation/privacy/navigation cases pass 35.9s after the final actor/route/native-ID context guard. TypeScript, production build and whitespace checks pass. Source tests exercise confirmation/escape, exact identities, real Connect-shaped accepted-response-loss fixtures, reload/Get-only recovery, unknown/rejected phases, unsupported targets, malformed receipts, corrupt metadata, account epochs, retained success through own refresh, and dark/light desktop/mobile fonts and layout. They do not prove native HTTP effects, a durable PostgreSQL journal, active external races or recovery. Root owns independent schema061 native/served and recovery qualification before any readiness claim.
