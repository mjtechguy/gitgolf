# Inline review-comment reads

Initial generated API, UI, CLI and MCP read increment, 2026-10-03. The [native characterization](PULL_REVIEW_COMMENTS_NATIVE_QUALIFICATION.md) established the supported native behavior independently on a since-retired backend; it has not been repeated on Forgejo 15.0.9. Final running Golf proof is recorded in the [implementation ledger](IMPLEMENTATION_STATUS.md); implementation or native counterpart tests alone do not qualify the deployed Golf path. This extends the overall [review mutation contract](PULL_REVIEW_MUTATION_CONTRACT.md); it does not implement inline write/draft/reply/resolution workflows or protected merge authority.

## Identity and bounds

`RepositoryService/GetPullRequestReviewComments` requires `repository`, exact positive decimal `repositoryId`, `pullRequestId`, `reviewId`, positive `number` and the full lowercase40/64-character `reviewCommitId`. Big IDs remain strings. Responses contain the same repository/PR IDs, the independently observed review, its complete bounded native `comments` array and the currently observed PR head. Deleted/unresolved source metadata can leave that current-head field empty; it is not fabricated freshness.

The supported native `/pulls/N/reviews/ID/comments` endpoint returns the entire array and ignores page/limit. Golf refuses more than100 comments rather than truncating them or inventing continuation. Native JSON remains bounded to2MiB, each body to256KiB and each stored hunk to64KiB. Literal safe paths use the source-path contract. Exactly one old/new file line must be positive and within1–2147483647. IDs are unique, positive signed64 decimals; comment review IDs and PR URLs must match. Display URLs bind the exact native PR/files path and `#issuecomment-ID` fragment. URL metadata is never an outbound request destination.

The repository/native caller/PR are observed around the read. Native review ID, selected commit, summary/flags/timestamps and comment count are checked before and after the complete array; changed review headers refuse the response. Caller-owned PENDING is readable, while other-user pending reviews are rejected before fetching comments even if an upstream route is too permissive. The entire operation has a15-second child context. Read-only delegated Golf API credentials can use this explicit procedure under their current source authority; they cannot publish or resolve comments.

Native map traversal does not define order. Golf sorts by parsed creation time, then exact numeric comment ID. Counts and checks are observations, not a lock or atomic collection snapshot: a concurrent body or resolver edit can leave the count/header unchanged. No result authorizes merge or determines eligible approval.

## Native meaning and presentation

`oldLine` maps native `original_position`; `newLine` maps native `position`. These are old/new **file** lines. They are not patch offsets, current/original remapped positions, multiline ranges or thread identifiers. Native `commitId` is line/blame metadata and can differ from the review's selected head. `originalCommitId` can be empty; it does not supply the original reviewed base. The native path, side, line, body, hunk and commit metadata can remain unchanged after head movement, rename or deletion. Never use them alone to invent a current source/diff location.

The generated comment preserves body, author, path/side, owning review, native commit/hunk metadata, timestamps and optional resolver identity. `resolved` observes non-null native resolver presence **per comment**, before a deleted/ghost resolver's unavailable identity is dropped. A marked parent and an unmarked same-line reply can coexist. This is not resolution of a fabricated thread or entire location. Missing/deleted authors and resolvers remain explicitly unavailable identities.

The UI opens inline comments only after an explicit action on a visible review, in Conversation or the explicitly opened Files changed comments panel. It reuses shared compact comment headers, safe Markdown, dates and global styles. It exposes literal native paths and old/new lines, individual resolver observations, escaped optional hunk/metadata disclosures and independent current/earlier/unavailable-head labels. Native review stale/dismissed flags remain separate. No source links are inferred from blame commits or empty old refs. Private bodies, paths, filters and hunk content stay in memory; closing, selection changes, sign-out or denied live access removes them. Current-authority revalidation conceals old content while waiting; an explicit inline-comment refresh remains available while live because direct native body/resolver edits do not produce Golf journal events. This refresh replaces the private observation; it does not claim automatic external-producer reconciliation. Constant PR tabs remain stable during private-content revalidation to preserve keyboard navigation.

The Files changed panel reuses overall Reviews and ordinary PR discussion, giving code reviewers context without navigating away. Full anchored line interactions, persisted private drafts, replies, edit/delete, suggestions, whole-file/multiline comments, correct original/current mapping and complete conversation resolution still require implementation and verification. [GitHub's current comment-panel reference](https://github.blog/changelog/2026-02-19-access-all-pull-request-comments-without-leaving-the-new-files-changed-page/), [review comments](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/commenting-on-a-pull-request) and [REST comment coordinates](https://docs.github.com/en/rest/pulls/comments).

## Agent interfaces

```sh
./bin/golf pr review-comments OWNER/REPO NUMBER REVIEW_ID \
  --repo-id REPOSITORY_ID --pull-id PULL_REQUEST_ID --review-commit FULL_REVIEWED_SHA
```

Supply the exact displayed native bindings. There is no automatic object lookup or pager. The existing temporary PAT session is signed out before successful JSON is emitted; credentials are not copied to output. MCP exposes `golf_pr_review_comments` with all six required fields: `repository`, `number`, `review_id`, `repository_id`, `pull_request_id`, `review_commit_id`. PAT and owner-issued read-only bearer modes retain their distinct session semantics. These are review reads, not review publication or automatic agent authority.
