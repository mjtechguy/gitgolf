## Discussion reads

`RepositoryService.ListIssueComments` takes the repository address, expected immutable repository ID, issue number, expected immutable issue ID and an explicit page. Native IDs are canonical positive decimal strings. The target must be an ordinary issue, not a PR exposed through the native issue API.

The native issue-specific comments endpoint ignores page/limit (characterized on the since-retired backend; Forgejo inherits this code but it has not been re-qualified). Golf therefore requests one bounded page from the supported repository-wide comments endpoint and filters exact ordinary-comment issue URLs to the requested issue. It returns no unrelated bodies, PR comments or native repository-wide totals. Empty filtered pages can have `nextPage`; callers must follow continuation. It does not scan unseen pages automatically or claim a snapshot/completeness guarantee while native comments are being edited/deleted. Native page/response and Golf transport bounds remain enforced; excess data fails visibly instead of being silently truncated.

Target IDs and current caller/native access are checked around reads. Provider URLs are validated metadata, never destinations for outbound requests. External bodies are bounded to 256KiB and issue titles to 1024 bytes; native JSON is bounded to 2MiB, with page size at most 100 and page ceiling 10000. Excess data fails visibly. Comments and issue bodies use the shared safe CommonMark/GFM renderer, sanitized HTML and bounded code highlighting. Context-free discussion images remain unavailable placeholders; attachment delivery is separate work.

## Create an issue or comment

`CreateIssue` requires the repository address/expected ID, title, body and a canonical lowercase UUIDv4 `idempotency_key`. `CreateIssueComment` additionally requires the displayed issue's number/expected ID. Only browser-session authority can invoke these writes; read-only API credentials and local MCP tools cannot.

A title is trimmed, nonempty UTF-8, at most 255 bytes and contains no controls. Bodies preserve exact valid UTF-8 and are at most 6000 bytes; comments must contain non-whitespace text. Only tab, LF and CR controls are accepted in bodies. The 6000-byte cap keeps worst-case JSON escaping plus bounded metadata within the existing 16 KiB Connect request boundary. This is an explicit input ceiling, not truncation of submitted content.

Create, comment and update operations share an owner/forge/key journal. Exact canonical input, operation kind and target IDs bind a fingerprint; stored records contain metadata/digests, not request titles/bodies or provider credentials. Reservation plus the initial `OUTCOME_UNKNOWN` event commit before any native POST/PATCH. Only the invocation that created that reservation may dispatch. Repeating a key with identical input reads recorded evidence; different input fails precondition. A key is never reused to retry a provider write, including after cancellation, process failure or restore.

Known preflight target-ID mismatch records `REJECTED`/`target_changed` without a POST. Qualified explicit native denials may also be rejected. An exact native HTTP 201 receipt matching actor, target address and submitted text first records immutable provisional `observed_result_id`/`observed_number` metadata with a `RECEIPT` event while the operation remains unknown. Only a subsequent current ID-bound postflight records `SUCCEEDED` with its immutable issue/comment identity and terminal event together. Provisional IDs are diagnostic evidence, never permission to adopt an object or present success. A crash or storage failure before receipt commit can still lose that observation. Lost acknowledgment, malformed responses, post-dispatch target mismatch and uncertain effects remain `OUTCOME_UNKNOWN`. The state is evidence, not an HTTP success promise; do not automatically resend or adopt a similarly worded issue/comment.

`GetIssueMutation` reads the issuing account's historical record. Foreign keys are concealed. Returning an optional current issue/comment also requires current native access and exact recorded object/target binding. Historical success cannot grant access to a deleted, moved or replaced object. Outcome bookkeeping after response loss is bounded synchronous storage work and does not issue another provider request.

## Edit, close and reopen ordinary issues

`RepositoryService.UpdateIssue` is browser-session-only. It takes the repository address, expected immutable repository/issue IDs, issue number, displayed `Issue.revision`, a UUIDv4 key and **exactly one** optional title, optional body, OPEN/CLOSED state, milestone-change, label-change or assignee-change wrapper. Optional body presence distinguishes clearing the body (`""`) from leaving it unchanged. Pull requests are refused. Input caps remain255/6000 UTF-8 bytes. `UPDATE_ISSUE` shares the existing metadata-only journal and issuing-account status lookup; no CLI/MCP write is added.

The revision hashes issue ID, number, author ID, native `content_version`, title, body, state and updated timestamp. Missing/invalid native version disables browser actions. After current repository/caller/issue binding, a changed revision records `REJECTED/revision_changed`; an unchanged selected field records `REJECTED/unchanged`. Neither dispatches a native PATCH. A pending editor retains its original revision through background access checks. A rejected stale edit closes on **Review current issue**; the user must explicitly reopen an editor against current values. Golf never silently rebases the draft or generates a retry.

One native PATCH sends the selected field and observed `content_version`. Its HTTP201 receipt must bind the same ordinary issue/address/author and exact selected value. Provisional receipt metadata commits before the independent current-access readback; success additionally observes that value again. Lost responses, malformed receipts, changed postflight fields and caller revocation leave uncertain evidence without another PATCH. An explicit403,409 or412 denial is rejected. Current optional result objects are current observations, not immutable snapshots of submitted text.

Native author or issue-unit write permission governs title/body/state changes. Actual local qualification proves owner/writer edits, a read-role user's own issue edit/close, reader denial on another author's issue and outsider denial. Golf does not infer issue-write authority from code push permission and does not yet expose a per-action `canEdit` observation: offered controls still check native permission when saving. Native permissions and `write:issue` credential scope are distinct.

The pinned handler is **not transactional across title/body/state**, so mixed-field submissions are refused. Body changes use native `content_version` conditional admission; the native stale-body409 case is qualified. Title/state check the version before changes but still have a concurrent-write window. Golf revisions/preflight/postflight do not establish atomic whole-issue CAS, an expected-ID address fence, full unit-policy enforcement or protected merge authority. Native events/notifications/hooks may run. These limitations remain explicit developer-preview boundaries.

## Issue label and milestone editing (schema066)

`ListRepositoryMilestones` and `ListRepositoryLabels` expose paged, current-authorized native inventories and separate editing flags. Read-only API credentials can read authorized inventories but receive false editing flags. This initial editing slice requires a current native repository owner/direct administrator/organization owner; Golf instance administration supplies no override. Archived repositories refuse writes. Broader issue-unit writers, organization-label selection and PR metadata remain open; the bounded assignee slice is described next.

A milestone wrapper freezes independent expected/selected IDs;0 clears it. A label wrapper freezes `expected_label_ids` and selected `label_ids`; an empty selected set clears it. Label sets are sorted unique canonical positive decimal IDs, capped at256. Expected IDs preserve full signed-int64 native identity, while new selections are additionally capped at9007199254740991 to avoid the pinned native handler's float64 conversion. Unsafe current selections can be removed. Current/selected labels must bind to the repository; inherited organization labels refuse this repository-only replacement. Conflicting exclusive-label groups refuse before native silent deduplication. Native archived-label flags are retained without inventing a selection ban.

The original issue ID/revision and independent metadata expectation are checked before dispatch and after native inventory waits. Metadata is not part of the original title/body revision, so that separate expected-ID/set check is mandatory. The journal retains existing fingerprints for previous operations and adds the selected field to the new canonical intent. Mixed fields refuse before reservation. One PATCH changes a milestone; one PUT replaces labels. The label response contains only labels and cannot establish immutable issue identity: only an independent current-authorized exact-issue/label-set GET supplies receipt identity and success. Lost/ignored/inconsistent effects remain unknown, with original-key inspection and no repost. These native observations do not provide atomic expected-ID/set CAS.

The shared sidebar pencil opens compact inline TanStack Form controls. Unknown current metadata, revoked access or immutable issue replacement clears editing readiness; choices/drafts never migrate to a replacement issue. Current-auth checks, explicit error retry, keyboard entry/focus return, theme/mobile and durable reload inspection are exercised. Exact source and actual native role/stale/readback evidence are recorded in the [implementation ledger](IMPLEMENTATION_STATUS.md#labels-and-agent-monetary-limits-current-deployment-2026-10-05).

## Issue assignee editing (schema066)

`ListRepositoryAssignees` takes the repository address and exact repository ID, returning current native candidates and `can_edit_assignees`. The supported native endpoint is unpaginated: Golf bounds the complete response to1000 candidates and refuses overflow/malformed or duplicate ID/login pairs. There is no fabricated PageRequest. As with milestone/labels, native owner/admin and active issue-unit authority govern editing, and delegated read-only API credentials receive a false editing flag.

`UpdateIssue.assignees` contains numerically sorted unique positive canonical int64 `expected_assignee_ids` and at most100 selected `{id,login}` pairs, with unique case-insensitive logins. The wrapper is required for explicit clear; an empty selected set serializes to native `assignees: []`, never null or legacy singular `assignee`. Candidate discovery is not guaranteed assignability: selected ID/login pairs must match current inventory and each selected native `/assignees/LOGIN` check must return204. This is up to100 native checks within the existing15-second bound; timeout refuses dispatch. Only retained/new selections need current eligibility, so removed stale candidates require no selection check. Equal-ID/no-op requests still pass those current observations before unchanged classification.

The independent current expected-ID set, immutable issue/repository, displayed revision and native manager authority are checked around provider waits. A single-field PATCH201 must bind the same issue/address/author and exact selected user ID set; separate current-authorized readback gates success. Changed identity/login, wrong/lost/ignored responses, permission loss and inconsistent readback retain the established rejection/uncertainty boundaries with no replay or automatic rebasing. Native name/ID/permission races remain observational, not target-side CAS.

The shared inline pencil editor merges original current users with loaded candidates so unavailable current users can be removed, with loaded search, a global bounded scroll area and explicit100-selection ceiling. It freezes the original intent and selected login pairs; unknown current metadata, issue replacement or revoked access disables/removes private editing as documented above. Exact source and actual-native acceptance, including the narrower retained-nonassignable qualification, are recorded in the [implementation ledger](IMPLEMENTATION_STATUS.md#issue-assignees-current-deployment-2026-10-05).

## Native-address limitation

The pinned native POST routes address repositories by owner/name and comments by issue number; they have no expected-ID predicate. Golf's preflight and verified postflight establish observed results but cannot atomically prevent a native rename/delete/reuse during dispatch. A mismatch after dispatch can mean an effect occurred at another native address, and remains unknown rather than becoming a successful Golf observation. Neither an account lock nor a receipt check is a target-side conditional write fence.

This limitation remains a release qualification gap where the plan requires conditional target admission. It does not weaken the separate protected Git/source/base/approval gates, qualify the separately documented PR mutations or claim exactly-once external effects. The current supported-native-address workflow follows the selected native forge integration; a required conditional workflow needs a supported enforcement design and its own complete race corpus before it can be advertised as qualified.

## Authentication and client behavior

Native writes require `write:issue` plus the scopes used for caller/repository binding (`read:user`, `read:repository`). Native issue-unit permissions still govern access: a native read-role may allow reporting/commenting, so Golf does not equate that label with a zero-write role. New browser OAuth grants request `write:issue`; existing `read:issue` grants are not silently upgraded. Revoke the old Forgejo grant and obtain fresh consent, or use a dedicated appropriately scoped PAT. Managed identity/role policy remains separate work.

The browser freezes one UUID-backed intent, prevents duplicate submission and offers status inspection after uncertainty. Reload only inspects a pending operation; it never reposts. Convenience storage contains only key/kind/target metadata scoped to exact origin/native user/repository ID, never titles, bodies or credentials. Authentication/access loss clears private discussion/form state. A terminal rejection permits an explicit new intent; an uncertain operation does not become an automatic retry.

CLI/local MCP add comment-page and own-operation-status reads to the existing authorized dispatcher. They preserve explicit empty-page continuation and conservative MCP annotations. There are no new write commands/tools or agent approval semantics.
