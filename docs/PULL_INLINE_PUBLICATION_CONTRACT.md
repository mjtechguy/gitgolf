## Scope and authority

An explicit action publishes one exact saved private Golf review version as `COMMENT`, `APPROVED` or `REQUEST_CHANGES`, including 1–20 bounded inline entries. It uses the supported native review-creation API once. It does not create/synchronize a native PENDING working draft, infer thread ancestry, execute inference/CI or merge code. The portable and Cloudflare tracks share this contract; AI and Cloudflare remain optional.

| RPC | Intent / result |
| --- | --- |
| `PublishPullRequestReviewDraft` | Exact `target`, `draftId`, positive canonical decimal `expectedVersion`/`expectedTargetGeneration`, `comparisonId`, fresh canonical UUID `operationId`, and supported `decision`. Returns only the publication mutation. Text/source come from the encrypted saved version, not replacement browser fields. |
| `GetPullRequestInlineReviewMutation` | Current authorized target, exact owned draft UUID and operation UUID. Reads the original receipt; never dispatches, resumes a reservation or adopts a similar native review. |

Both procedures require the existing managed Golf browser session, exact configured Origin and currently authorized native identity/target. PAT/bearer delegation is denied, including status reads. Administrator status grants no other-owner override. Current routing names locate a target; native repository/PR IDs identify it. Authority is rechecked around provider waits and receipt disclosure, and managed owner/session locks revalidate expiry/revocation. These observations do not lock external native authority or refs. See the existing [private draft contract](PULL_REVIEW_DRAFT_CONTRACT.md) for retained-source and credential boundaries.

## Exact saved selection and coordinate admission

For a valid saved collection, the server freezes every ordered body/path/side/coordinate before semantic admission. Reservation binds the current nondeleted saved version, permanently retained target generation, immutable comparison UUID and original native actor. A delayed save/delete/recreate request cannot select another version or reset generation. Deterministic request and ordered native-payload SHA-256 fingerprints bind the operation and exact body/entry order. Immutable journal metadata retains the original revision, target branch tip **B**, actual merge base **M**, reviewed head **H**, diff SHA-256, decision and entry count. M→H is the old/new comparison; B and child line/blame commit IDs are not substitutes for M or H.

Before native dispatch, Golf requires the original revision, B/M/H, retained PR head and complete raw diff to match independently observed current native state. The PR must be open, ready and unmerged. Its author may comment but cannot approve or request changes. COMMENT and REQUEST_CHANGES require a nonempty saved summary; APPROVED permits an empty summary. All entries still require bounded nonempty bodies. An earlier retained draft remains readable/editable under current authority, but this packet does not publish it against a changed selection or silently remap it.

The shared strict parser validates exact file/hunk indices, literal path, OLD/NEW side and positive signed 32-bit line coordinate against server-retained bytes. Native publication is narrower than private working storage: qualified single lines in ordinary same-path files, with the selected side available. Renamed/deleted paths, binary/submodule/metadata-only or ambiguous coordinates, malformed/overlapping hunks, CR/unsafe controls, long scanner rows and unsupported retained-native-context bounds are refused before dispatch. Supported OLD/NEW context is checked independently; two positive side coordinates are not a range.

Inherited bounds include 20 entries, 6000 UTF-8 bytes per body/summary, 4096-byte safe paths and 512KiB/500-file/12,000-row original comparisons. Admission also budgets JSON-escaped request/body/path envelopes and every retained child hunk against the existing 2MiB native response bound; a small raw-text payload can still be too large when escaped or repeated. Native child hunks are bounded 64KiB. Publication history is limited to 1000 operations per owner / 10,000 per instance; no purge is enabled.

## Reservation, shared exclusion and outcomes

Additive migration 037 stores immutable publication metadata and append-only events in Golf-owned tables. Foreign keys retain the exact schema 036 SAVE/comparison records, whose private text/source remain encrypted in the existing `review_content` AEAD family. No plaintext body, path or diff is copied into the new journal. Existing encryption startup, rotation, key retirement and historical-content retention continue to apply. Deleting a private working draft does not erase its accepted publication or release uncertainty. A valid empty working collection may be journaled with entry count 0 to retain its rejected intent; SQL prohibits SUCCEEDED unless the count is positive.

A transaction-scoped native-actor/repository/PR reservation gate is shared with human overall-review mutations 034 and managed reviewer publication 035. Unresolved inline reservations/dispatches, overall unknown effects, managed reviewer reservations/unknown effects and retained legacy effect blockers prevent another Golf publication in that domain, including new keys, draft versions/generations or reviewer configuration. This is Golf reservation ordering; direct native writers are outside the gate.

| Phase | Meaning / permitted next action |
| --- | --- |
| `RESERVED` | Immutable local intent accepted; the original invocation may still be running. Status reads cannot send or resume it. A stranded reservation remains a blocker. |
| `REJECTED` | Known refusal before native POST, recorded as `preflight_refused`. The exact operation is immutable and inspectable. Only an explicit new action may prepare a new operation for the still-valid saved version. |
| `DISPATCH_UNKNOWN` | Dispatch intent committed before the single native POST, or effects/readback remain uncertain. An observed review ID may be retained; no verified child IDs are returned. Inspect the original operation without retrying or publishing remaining comments. |
| `SUCCEEDED` | Complete independent header/child/context and postflight authority/selection verification succeeded. Positive distinct child IDs correspond to the original intended entry order. This is historical publication evidence, not current approval eligibility or merge readiness. |

Exact-key replay returns the accepted mutation without another POST. Changed intent under that key is refused. A nonrejected operation also prevents another effect for that saved version. Native 500/422, lost/canceled responses, SQL acknowledgement failure, mismatched/partial receipts, source/authority changes after dispatch and concurrent absorption cannot prove no effect: Golf retains uncertainty rather than compensating, resending or inventing success. A browser error without an independently observed REJECTED receipt is not a safe retry instruction. Valid saved semantic refusals—including empty collections/summaries, unsupported renamed/deleted paths and aggregate receipt budgets—now reserve the complete fingerprint under the same actor/target gates before returning a durable REJECTED receipt. An existing unresolved effect takes priority; a rejected semantic intent cannot bypass that gate. Malformed UUID/counter/decision, invalid/decryption-failed saved payload, missing current authority, storage uncertainty or an unknown effect do not gain a fabricated refusal/no-effect receipt. If reservation storage fails, a possible durable RESERVED remains inspection-only; no status repair invents rejection. No no-effect response header or private-body echo is added.

Each successful human overall-review (034) or inline-review (037) transition commits exactly one metadata-only `pulls` invalidation under the correct forge/repository, using the existing ordered repository activity helper. It exposes no private draft text or intent. Private Save/Delete, reservations, rejected/unknown effects and replays emit none. Activity refreshes authorized views; it is not a new publication or proof of current approval readiness.

The owner’s existing native PENDING review is checked across the bounded supported native paging span before creation and refused without adoption, submission or child modification. Native pending creation can race that check. Partial batches can leave pending children; this packet has no reconciliation, discard, resume or override operation. Status never promotes UNKNOWN merely because later content looks similar.

## Native receipt and postflight verification

The immediate review receipt and independently fetched header must bind native ID, exact actor, PR URL, intended decision/body, original H, nondismissed state, valid dates and exact child count. Golf reads the whole bounded child collection and then rereads the header unchanged. Every child must have a unique positive native ID, matching review/actor/PR/path/body, exactly one intended side coordinate, safe native URL and bounded valid metadata. The complete qualified native hunk cut must match the retained M→H comparison; an OLD-side prefix may end at the selected old row before replacement NEW rows. It need not contain the entire displayed hunk. Native line/blame commits remain separate metadata. Child iteration order is not assumed: the verified ID array is mapped back to immutable intended entry order.

After readback, Golf rechecks repository/PR IDs, retained head, B/M/H, semantic PR observation, complete raw diff and current caller authority. Native publication can change PR `updated_at`; postflight ignores **only that timestamp** when comparing the observed PR revision, while requiring other represented semantics and exact diff/ref identities to match. It does not attribute a timestamp change to Golf, detect every concurrent edit, fence native dispatch, prove approval freshness or establish merge readiness. A matching header alone is insufficient; child/context mismatch remains UNKNOWN.

## Browser behavior and remaining UX work

The source UI adds explicit **Publish saved review** to the private working collection, using shared TanStack/Markdown/styles rather than a settings modal. Opening freezes the saved version/comparison/generation. Unsaved working notes remain separate; a later saved-version change requires explicit close/reopen. Original M/B/H/diff fingerprint and saved content are inspectable. Older comparisons, unsupported PR state and self-decision controls cannot silently select new source.

Before sending, the tab stores only operation/draft/comparison UUIDs, accepted version/generation, decision and entry count, scoped by origin/user/native repository/PR. It stores no body/path/diff or provider credential. Reload performs status lookup only. Invalid metadata, transport errors and unresolved receipts prevent replacement publication. Only observed REJECTED allows an explicit new attempt. Publication leaves the private draft intact; success does not consume it or turn it into native PENDING. In the frozen first UI, a succeeded operation remains inspection-only under its per-PR key even after later draft edits. Bounded attempt history and an explicit newer-version publication flow are follow-up work; the UI must not silently erase the prior receipt.

Private content/receipt details are withheld during access revalidation and cleared on observed denial, logout/account change, pagehide/unmount; generation guards reject late responses and requests are canceled. Keyboard/mobile/both-theme behavior requires browser evidence below and actual served qualification. Remaining UX includes tighter end-to-end publication entry flow, native published-comment refresh/anchoring qualification, genuine reload/restart/two-device fault drills and explicit safe reconciliation of unresolved effects. No native draft adoption/edit/discard/submit, reply, per-comment resolve/reopen, published edit/delete/dismiss, multiline/whole-file/suggestions or delegated CLI/MCP write surface is completed by this control.
