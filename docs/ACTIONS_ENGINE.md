# Maintained Actions engine contract

Golf's maintained Linux engine uses pinned act v0.2.89 through a local runtime-source replacement. The combined source recognizes input-free `golf.workflow.act.v0.2.89.linux.v1`, opt-in manual-input `golf.workflow.act.v0.2.89.linux.v2`, the independently gated agent catalog, and the opt-in [public Node24 catalog](ACTIONS_REMOTE.md). Catalog recognition is not installation readiness or execution authority. The v2 source consumer and build contract are implemented, and one owned native/TLS1.3/Docker typed/default/literal/local-composite run qualifies on frozen source `33d16cdc`. Later typed-input/secret and served parameter/run proofs have their own receipts in the [implementation ledger](IMPLEMENTATION_STATUS.md); the broader runtime matrix remains open. This contract does not make full Actions/GitLab compatibility or CI settings Ready.

## Catalog and source binding

Both catalogs retain the bounded pinned Linux profile, immutable workflow/archive/local-action source identities, admitted image digests, resource limits, matrix/needs graph, synchronous execution observations and no automatic execution replay. The engine rederives the admitted plan from the original archive and requires exact plan equality before Docker effects. A claimed run does not become successful merely because an engine process exits: existing durable job/step/complete receipts and matching attempt authority are required.

V1 keeps its original catalog and denies input declarations/contexts. V2 admits only manual `workflow_dispatch` execution, with a full 40/64-character commit SHA and the explicit `golf.workflow.dispatch.inputs.v1` contract/schema binding. Inspection uses that same full source SHA. Input-free GitHub workflows retain v1 planning and legacy dispatch even on a v2-configured instance; typed mode requires nonempty declarations, while an empty submitted array using declared defaults remains v2. Undeclared input contexts remain unsupported. Push remains on v1, and declaring manual inputs does not imply push execution compatibility. Legacy GitLab shell execution remains separate and unchanged; GitLab variables have no typed Actions conversion.

The shared `internal/workflowinputs` parser defines string/boolean/number/choice declarations, presence/default rules, canonical maps and digests. The [manual-input contract](WORKFLOW_DISPATCH_INPUTS_CONTRACT.md) defines preparation, encrypted retention, admission, current-authority release, verified-TLS worker selection and original-operation inspection. Neither the worker's synthetic map check nor a caller-provided digest substitutes for the engine's independent source-schema/default check.

V2 permits `inputs` and `github.event.inputs` only in expression positions already admitted by the profile: workflow/job/step environments, job/step conditions, job outputs, step run/with, and supported local-composite input defaults/output values/steps. AST validation keeps other denied platform/provider/authority contexts denied. Inputs do not select images, resources, runner authority or expand the graph. Existing static matrix, needs, output and local-composite limits remain. Declaration descriptions/options/defaults containing `${{` are still refused; submitted string expression-looking text is inert data.

Schema060 adds a source-implemented typed manual secret-release consumer. A fresh repository approval binds the input contract, schema, canonical submitted/effective digests and existing source/value identities; no v1 approval can silently forward values into v2. See the [typed execution-value contract](TYPED_EXECUTION_VALUES_CONTRACT.md). Actual schema060 Docker/TLS-worker and served approval qualification remains pending. Environment selectors, protected environment gates, external providers, broader operating systems and the rest of the full compatibility plan remain separate requirements.

## Narrow act adaptations

The pinned upstream evaluator already exposes dispatch booleans differently from string-valued event inputs. Golf adds finite numeric conversion only for declarations of type `number` in the `workflow_dispatch` evaluator branch. Canonical event inputs remain strings. Server, worker and engine validate finite safe binary64 numbers and maps before execution; the adaptation alone is not an input admission boundary.

The second correction preserves inherited, already-resolved composite `INPUT_` environment values during child `setupEnv`. Without it, expression-looking parameter data could be evaluated again. Nested scopes and same-name input collisions retain their own data; explicit source-defined step environment overrides still interpolate. This does not disable ordinary source expression evaluation or change generic property lookup. Case-fold-colliding declaration names are refused by the shared parser because the upstream map lookup is case-insensitive.

Regression families exercise public job evaluators and private native step/composite setup, true/false/default booleans, numeric `toJSON` versus event strings, decimal/zero normalization, nested composite scope, literal `${{...}}`, explicit source overrides, and unchanged matrix/needs semantics. Bad maps/types/digests/schema/event bytes are refused before effects. Tests that substitute an executor prove composition semantics only; they are not actual container-execution evidence.

Git source jobs additionally opt into local-driver tmpfs volume options and tar transfer through `docker exec`. Five native files carry that adaptation, including the trusted per-step credential hook; their original bytes and reproducible `readonly-copy.patch` are included in the same closed manifest. The default upstream copy path remains in use for legacy archive jobs. Docker archive writes cannot be used for this profile: real rootless qualification exposed writes beneath a tmpfs mount and read-only-root refusal. The trusted transfer uses fixed argv and stdin, with subsequent source/metadata/native Git readback before setup acknowledgement.

## Native workflow directory profile

Application admission supports direct literal `.gitea/workflows` and `.github/workflows` paths using Gitea 1.27.3 first-existing-directory selection. The operator order is shared with native Gitea; a suppressed directory cannot be directly dispatched. This changes inspection to v3 and does not change the engine execution catalogs or activate the agent catalog. Nested/custom workflow locations remain unsupported. See the [current path/evidence register](compatibility/README.md) and [inspection contract](WORKFLOW_CONFIGURATION_CONTRACT.md).

## Reproducible source and licenses

`engines/act/go.mod` replaces `github.com/nektos/act` with `./third_party/act`. The module cache remains unchanged. The exact upstream version is v0.2.89, source commit `4f411281417e88660bea1c1a1749aa71ae0bd60f`, tag object `434d69682c7a8db2ac913e5dc3e80ba68055d50d`. Original module ZIP SHA256 is `b4e568212d680a32076455b84ab572d17fe65eb83a6fd6dce6a05164bd68fcc9`.

The local runtime contains 86 upstream files, including the unchanged module files, full MIT license and required runtime embeds, plus ten Golf baseline/patch/regression files. `upstream_source_manifest.json` records the closed 96-file inventory, exact current and original upstream hashes, source pin and patch hash. The manual-input two-file adaptation patch SHA256 is `1df7c201fdc776159c458a0185b5777e09f08b6790a29968444992b5fa695e3e`. The separate five-file mounted-copy/credential-hook patch SHA256 is `fab694a362e1c4d8d405cb7d60f53756382e1e97468a4e6d31b7c4ce666dfbf8`.

`verify_upstream_source.py` rejects extra/missing files, symlinks, modified modules/licenses/embeds, wrong baseline bytes or a patch that cannot be reconstructed exactly. `--upstream-dir` independently compares every recorded baseline with a local pinned upstream source; `--self-check` demonstrates rejection of seven tampering cases. The required embeds retain their original bytes: hashfiles JavaScript, runner trampoline JavaScript, workflow schema and action schema. The verifier performs no downloads, builds or module-cache writes.

`make engine-check` runs verification, nested engine vet/tests and the private runtime regression package alongside root checks. Both `deploy/docker/Dockerfile` and `deploy/docker/Dockerfile.runner` verify the source before building their engine binary. The runner build includes `internal/workflowinputs`. Both final images copy act's MIT license, the lookpath MIT notice and the container Docker Apache-2.0 notice into `/usr/share/licenses/golf-actions-engine/`.

Image qualification must retain the product revision, baseline/patch/manifest/verifier hashes, exact engine and runner binary hashes, image identities and test/cleanup evidence. A closed self-verification against the checked-in manifest is distinct from an independent upstream-baseline check. A source commit, successful build or advertised catalog does not prove the installed worker executes v2 correctly.

Frozen component `557b9de45f7f97609636b967e0c861a0ff626c89` binds each inspected private workspace and command-file volume to one container for the entire attempt. A volume cannot alias both private mounts or carry into another job after its earlier container exits.
