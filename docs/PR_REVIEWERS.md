# Managed PR reviewers

Golf's initial reviewer uses a connected OpenCode Go account and an operator-enrolled native publishing bot. Configure its name, description, review focus, exact account/model/variant, PR-open/new-commit/mention triggers and expiring sponsorship under repository Settings → Workflows. Current repository owners/admins can edit it. Instance, organization when applicable, repository and personal-account policies independently restrict use. A default account at a shared scope must be an explicitly shared instance connection; an individual's reviewer can select their personal account within policy ceilings.

The runtime receives a pinned PR diff, title and authorized question. It cannot use tools, edit files, run tests, read project instructions, load project plugins/MCP or obtain forge credentials. Native tools are disabled and checked against the pinned CLI's resolved agent at worker startup. The task uses a nonroot, read-only Docker container with dropped capabilities, no privilege escalation, bounded CPU/memory/processes and private tmpfs credentials/cache. The native executable is packaged directly at version 1.18.34; auto-updates are disabled. API requests remain subject to the connected provider's terms and usage limits. No fallback provider/model or additional billing credential is selected.

Golf validates typed JSON findings against actual paths/new-side lines in the captured diff. Summary and findings are bounded, rendered as plain text in Golf and escaped for native review Markdown. The trusted publisher submits a native COMMENT review and inline findings at the exact head commit. It submits advisory pending/success/failure/error statuses through the current sponsor's authorized credential. These statuses neither authorize protected merge nor establish vulnerability absence. Source/policy/account/reviewer authority is checked throughout execution and immediately before publication; native APIs still have an external race after preflight. Stale snapshots stop work or remain explicitly historical. No automatic approvals, changes-requested decisions, edits, pushes, merges or deployments occur. The [publication boundary](REVIEWER_PUBLICATION_CONTRACT.md) specifies exact identity/merge-base capture, strict coordinate admission, pending preflight, independent complete receipt verification and durable uncertainty; its source and native-helper proof are separate from the historical provider qualification below.

## Sponsorship and identity

A saved enabled reviewer explicitly delegates the current local Golf account's mapped forge credential for up to 30 days. Each admitted task receives its own short-lived, account-version-bound session; browser sessions are never copied or reused. Browser logout does not revoke this explicit delegation. Reviewer disable/edit/expiry, local account disable/password reset, loss of native repository administration, model disconnect/use revocation or policy changes prevent further authorized work. Completed terminal review sessions are removed; abandoned sessions remain bounded by their native 12-hour lifetime.

The publishing credential is a separate private operator secret (`GOLF_REVIEW_PUBLISHER_TOKEN`) for a non-site-admin native user. The operator must grant that bot read access to each private repository. Initial publisher enrollment/rotation is an operator workflow, not an arbitrary token field exposed in the reviewer editor. This account is visibly named as a bot in the posted review and configuration. Its token never reaches the task. Model credentials continue to use Golf's existing encrypted connection/cache lifecycle; no new database credential domain is introduced.

## Initial scheduler and outcomes

The first local coordinator polls the first 50 open PRs and first 50 comments for at most 25 enabled repositories per pass. It shares the existing conservative managed worker queue. Only open, nondraft, same-repository PRs and bounded ordinary text diffs are supported. Mention handling accepts the sponsoring native administrator or the current PR author and the exact `@bot-login` token, avoiding other contributors and bot loops. An authorized mention starts another security review with the question; this is not unrestricted conversational shell access.

Each observed base/head pair has a durable unique automatic receipt. A review task cannot dispatch until its durable review receipt is linked; failed intake cancels any queued task. An explicit request ID or comment ID has one receipt across later head changes. Repeated polling does not create another attempt; an old comment is not replayed on every push. A repository admits at most 20 hourly/outstanding reviews. Model/provider failure, worker loss and validation rejection require explicit inspection before a new authorized intent; Golf never automatically replays a model task or reposts a review. Native SDK/provider transport retries can occur within one attempt before the native process returns. A native publication reservation occurs before POST; ambiguous outcomes stay `publication_unknown` or `publishing` pending inspection and block fresh intents for the same publisher and target. Head movement and reviewer changes cannot clear them. No automatic reconciliation exists. This bounds duplicate risk but does not claim exactly-once external effects.

PR discussions extend the existing durable issue-comment journal with an explicit, immutable PR type. Ordinary issue requests continue to exclude PRs. PR issue IDs are resolved independently of native pull IDs, and native comment association binds both the displayed PR URL and HTML fragment. Unknown receipts are retained and inspected without adopting same-text comments or repeating POST.

## Deployment and qualification

Compose accepts optional `.env.review` alongside `.env.agents`. After starting the existing local agent profile, `python3 scripts/init-review-env.py --publisher-token-stdin` builds/loads the pinned runtime and writes private `.env.review`; repeat without that option to preserve the enrolled token. The helper targets the local Compose dedicated daemon. Enroll an exact locally loaded `GOLF_REVIEW_IMAGE` built from `Dockerfile.opencode` and the private publishing token. Reload Golf and the managed worker after changes; recreate the pipeline runner whenever Golf's service network namespace changes. Kubernetes/Cloudflare agent execution and broader GitHub/GitLab event scheduling remain separate qualification work. Canonical recovery still refuses newer schemas until explicitly allowlisted; reviewer work does not extend the recovery qualification.

Required live evidence: import pinned licensed public source into an owned private local repository; enable only the requested scopes/model; introduce a real flaw; observe actual model inference and native bot/inline/status receipts; push a parameterized fix and observe an automatic clean review; mention the bot through Golf's comment journal; verify no polling duplicates and no publication after authority/head changes. No successful inference or complete CodeRabbit/GitHub parity should be inferred from account connection or compilation alone.
