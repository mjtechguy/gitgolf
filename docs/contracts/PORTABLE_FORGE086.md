# Portable forge086 source contract

This extends the existing forge078 supported native API workflows. It adds no infrastructure service and does not enable repository CI. Schema086 source qualification is separate from the currently deployed localhost082 installation.

## Personal provider connections and selected imports

`ProviderImportService` uses managed Golf browser sessions only. Connections are personal, bound to the current Golf user, configured forge and numeric native actor. GitHub and GitLab.com use fixed HTTPS API origins, with redirects refused. The user supplies a provider personal token for an explicitly selected project; Golf does not crawl private repositories. Token identity is checked against the provider `/user` response, encrypted with the existing credential keyring, never returned by metadata APIs, and included in operator key usage/rotation/retirement.

Connections have immutable UUID/provider/account identity. Rename and revoke use an exact current version. Revocation is irreversible; a new credential requires a new connection. The initial inventory is capped at100 retained connections per user/forge. Recovery may revoke active connections and increment versions under the operator backup-bound quarantine audit without fabricating user events. This prevents future Golf use; it does not revoke the upstream token or undo a clone already accepted by the native forge.

`PreviewProviderImport` binds the exact connection/version, canonical selected source URL, provider project ID/privacy/default branch and its current commit. `SubmitProviderImport` retains the original UUID/fingerprint before dispatch; repeats provider authorization and the exact preview, creates a forced-private, own-account, nonmirror Git destination through supported `/repos/migrate`, and independently reads the native destination and default branch commit. Public projects do not forward the provider credential to the native forge. Private projects require the selected token to cross the explicit trust boundary into the privileged, configured native forge's supported Git clone credential input. No token is placed in the URL, Golf journal, browser cache, execution job or model input.

The verified receipt covers the private destination's numeric identity and exact observed default branch HEAD. It does not certify all refs/history, LFS, issues/reviews/comments, labels/milestones/releases/attachments, wiki/packages/boards, identity attribution, CI compatibility or policy migration. Those fidelity gaps remain listed in every receipt. Provider reads and native effects are not atomic: source drift, revocation, lost responses or failed readback may leave a durable `DISPATCH_UNKNOWN`. Inspection never resends or adopts an existing destination. One unresolved import per user and two per forge bound admission; these limits are not a Git clone resource sandbox or complete migration quota solution.

Deterministic fixed-origin authorization fixtures can prove selected private-source handling. Real private GitHub/GitLab fidelity requires explicit credentials and an owned source project; no third-party private project is sampled without that authorization.

## Bounded generic packages

`PackagePublicationService` publishes a fresh generic package name with one file (up to256 KiB), a version, original operation UUID and exact repository/owner/access identity. Initial publishing requires the repository's ordinary personal native owner. Organization publishing is refused because owner namespace membership has different package access than repository permissions.

**Native package privacy follows its owner namespace, not the linked repository.** A private repository requires a positively private owner namespace. Public or limited owner namespaces are refused for private repositories. A public repository under a public/limited namespace requires an explicit visibility acknowledgement. No owner profile visibility changes are performed. Golf/native writer locking does not turn namespace access into repository ACLs.

Before raw native upload and supported link dispatch, Golf holds its SQL repository lifecycle/protection gate and the exact owner/package name lock. Immutable unresolved name reservations prevent another Golf repository from bypassing that uncertainty. Native raw upload and REST linking are two effects; the bytes may exist in the native owner registry before linkage. After upload, version identity, publisher, owner, linking, file ID/size/SHA and downloaded exact bytes must all agree before success. A lost upload/link response or failed readback remains unknown, may leave an unlinked native package, blocks a fresh Golf attempt for that name and never triggers automatic resend/adoption. External native clients are independent, so all checks are observations, not a native compare-and-swap promise.

Generic downloads are mediated with the caller's existing native credential, independent package authority, current exact repository linkage, package/file IDs, bounded bytes (10 MiB), native size/SHA and repeated package/file observations. No bearer URL or credential is returned. Other package registries, organization publishing, replacement/deletion, multi-file versions, large streaming uploads/downloads and native client credential issuance remain separate unqualified capabilities.

Root integration registers the new browser service methods. Managed publication submit needs a384 KiB outer/Connect request cap for the base64-expanded256 KiB payload; downloads retain the existing16 MiB response cap. Native OAuth consent must include package write authority for publication; retained credentials are never silently elevated. Generated protobuf/sqlc artifacts are regenerated during root integration.

## Native wiki units and current navigation

The existing wiki write context now exposes `can_write` separately from general repository administration. Current ordinary personal ownership, direct collaborators and native organization team `repo.wiki` write grants are checked; a code push grant, aggregate native site administrator role or unrelated team unit does not replace that authority. Disabled/external/archived/mirrored wiki configurations remain refused. Permissions and the original page commit are rechecked before supported native writes. Native external writers remain independent of Golf's observation checks.

The supported current wiki GET includes separately bounded, safe UTF-8 sidebar/footer Markdown when supplied. These are current observations, not historical body snapshots, and omitted/empty native blobs are not fabricated. Same-wiki relative Markdown links resolve to canonical Golf wiki routes; account/admin/API paths, traversal, encoded path delimiters, unsafe schemes and credential-bearing URLs are refused. Rendering uses the shared Markdown sanitizer and media policy. Arbitrary external or wiki image proxying is not added. Native page history remains supported; historical body checkout, title renaming and richer Git-based wiki synchronization remain explicit acceptance gaps.

## Mirror completion observations

`MirrorObservationService.GetMirrorSyncObservation` is managed-browser read-only. Future original synchronization dispatches retain an immutable exact native timestamp/default-branch/HEAD baseline before the supported native queue request. Older originals without that baseline remain queue-only. Inspection never sends another sync request or converts an unknown dispatcher into an accepted queue receipt.

For an accepted original with a baseline, the configured source must be a canonical public GitHub/GitLab.com project. Reads use fixed HTTPS origins without any credential or followed redirect. The current native configuration must still equal the original revision, the current default branch must remain the same, and repeated public source/native observations must stay stable. `completion_observed` requires the native synchronization timestamp to advance after the original baseline and the native default branch HEAD to equal the observed public upstream HEAD.

This proves a later native synchronization and current default-branch equality; it does not attribute the effect solely to that queue request, prove all refs/history/LFS, or claim a private/arbitrary upstream verification capability. Source drift, native/configuration drift, unavailable baseline or unchanged/coarse native timestamps prevent completion claims. Private/unsupported upstreams continue to have the existing native synchronization controls with honest queue-only receipts.

Successful package publication appends one repository `source` activity notification in the same Golf transaction as its terminal journal transition. Unknown uploads, refused changes and exact replay append none, allowing existing shared SSE consumers to refresh inventories without copying package bytes or credentials into activity events.
