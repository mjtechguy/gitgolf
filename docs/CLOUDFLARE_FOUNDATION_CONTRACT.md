# Cloudflare foundation source contract

The foundation includes bounded account inspection, encrypted product account profiles, an operator D1/R2 resource consumer, an operator-configured protected-static-preview adapter, an authenticated Worker binding probe and repeatable disposable provider qualifications. The status ledger records exact passing evidence separately from source checks. Native product tenancy, application deployment, concurrent-agent product integration and protected PR previews retain their own gates.

## Operator-configured protected static preview

Source migration094 adds the optional `golf.repository.cloudflare-static.v1` adapter. It reuses the portable deployment, immutable artifact, approval and current-repository-reader checks. This first adapter binds one operator-configured deployment UUID per Golf process; it is not the automatic PR fleet provisioner or a migration093 allocation consumer. The preparation response reserves that UUID for the existing deployment UI. Local TLS previews and Cloudflare previews are mutually exclusive.

Configure a secure, separately hosted Golf origin and two owner-only regular JSON files (maximum32 KiB each):

- `GOLF_ACCESS_OIDC_CONFIG_FILE`: `client_id` (16–128 URL-safe characters), `client_secret` (32 random bytes in canonical unpadded base64url), `team_domain` (`<team>.cloudflareaccess.com`) and `private_key_pem` (PKCS8 RSA2048–4096 private key).
- `GOLF_CLOUDFLARE_PREVIEW_CONFIG_FILE`: `base_url` (isolated HTTPS hostname), `deployment_id` (reserved UUIDv4), `account_id`, `d1_id`, `r2_bucket`, `r2_created` (original provider creation time), `access_aud`, `broker_secret` (32 random bytes in canonical unpadded base64url), `probe_client_id` and `probe_client_secret` (scoped Access health credential).

These operator signer/client/broker secrets are private mounted files, not saved product account profiles. Existing encrypted Golf sessions remain in PostgreSQL. Configuration/resource/signer rotation changes the deployment fingerprint and invalidates the old target. Keep files and generated provider configuration outside version control; mount read-only for the Golf process.

Register one [generic OIDC client in Access](https://developers.cloudflare.com/cloudflare-one/integrations/identity-providers/generic-oidc/) with S256 PKCE, exact callback `https://<team>.cloudflareaccess.com/cdn-cgi/access/callback`, and Golf endpoints `/auth/access/authorize`, `/auth/access/token`, `/auth/access/jwks`. Discovery is `/auth/access/.well-known/openid-configuration`. The issuer is `<Golf origin>/auth/access`. Codes are hashed, single-use and expire after60 seconds; code exchange requires the confidential client, PKCE, current managed session and native identity. The `golf-<native ID>@reviewer.invalid` claim is an internal identity alias with `email_verified=false`, not a verified mailbox. Access policy admits only this registered login method; repository authorization remains Golf's responsibility.

An existing external Access seat can be reused with an explicit operator mapping: set both `access_reviewer_native_id` (positive native user ID) and `access_reviewer_email` (the exact identity returned by the trusted Access provider) in the preview JSON. Restrict the exact-host Access application to that email **and** the existing trusted login method. Only that native reader/email pair can redeem or use preview credentials in this mode; another Golf user or synthetic alias is refused. This mapping never changes Golf OIDC claims, enrolls the fixture as the real Google account, or grants repository access. Reviewers still authenticate to Golf, and the current repository/session checks apply on every request. Changing the mapping invalidates the target fingerprint. This is an operator-managed single-reader binding, not self-service account linking or a SaaS identity directory.

Create the exact-host Access application before publishing `<deployment UUID>.<base hostname>`. Preserve other identity providers and zone records. The Worker has no public workers.dev/version URL or static-assets bypass. `cloudflare/previews/wrangler.jsonc.example` describes its exact domain, D1/R2 bindings and nonsecret variables; `prepare.mjs` emits the native CLI build output used by the disposable qualifier. The Worker broker secret belongs in the provider secret store. Bind private R2 to the retained archive under `qualification/<archive SHA256>`, never arbitrary project-selected objects. Activation independently requires an anonymous Access redirect, valid HTTPS, authenticated exact target/artifact metadata and actual D1/R2 reads.

Opening a preview first completes Access login through normal Golf sign-in, then resumes the same-origin Golf handoff. Only after that redirect does Golf issue its60-second single-use launch grant. Trusted handoff documents use `Referrer-Policy: strict-origin` (including their HTML metadata), preserving the real form POST Origin while withholding paths/query strings. `no-referrer` would turn that Origin into `null` under the [Fetch standard](https://fetch.spec.whatwg.org/#append-a-request-origin-header), so it remains reserved for content/denial responses rather than trusted forms. The Worker redeems it at the secret-authenticated Golf broker; the host-only Secure/HttpOnly preview session lasts at most five minutes and remains bound to its live Golf parent. Every content request rechecks current native repository read access and the original deployment/environment/artifact. `/api/storage` checks authority before and after its D1 query and exact R2 archive hash verification. Access identity alone, the wrong reviewer, expired parent, control-origin cookies, caller-supplied JWT headers and alternate hosts cannot authorize project content. Golf credentials never enter project JavaScript. The health-only machine credential is not a general machine preview grant.

`python3 scripts/cloudflare-preview-smoke.py --profile golf --account-id <approved account> --zone-id <approved zone> --base-hostname <preview base hostname in that zone>` owns a disposable database, HTTPS quick tunnel, OIDC provider,20-minute health token, Access application, Worker custom domain/certificate, D1 database and private R2 object/bucket. Native CLI OAuth stays delegated to the selected profile. Pass `--reviewer-email <existing Google Access user>` only when that user authorizes testing: it verifies the occupied seat, reuses the one existing Google IdP without modifying it, and binds that identity to fixture reader42. The default external flow actually authenticates through Google. With explicit authorization to send a login email, add `--reviewer-login onetimepin` to create an owned temporary email-code provider instead; the reviewer enters the code in the browser. The application requires both the selected email and login method, and cleanup removes only the temporary provider. No email impersonation or shared service token substitutes for that authentication. The script waits for collaborative-browser evidence, records exact owned identities and tears down after success, failure or its bounded deadline. Its control-plane repository identity and runner-protocol producer are fixtures; it is not proof of a real PR, real candidate CI execution or PR-link publication. Local receipts live under `.tmp/cloudflare-previews/`. On2026-10-08, native TLS/Access health and Golf login continuation passed, but the Access callback refused human admission because all seats were occupied. The fixture identity was not added to the organization. That Golf-issued alias path still requires an available seat. A later authorized existing-seat/email-code qualification passes actual browser artifact/storage delivery and repository revocation, with both authentication sessions still live; see the094 ledger. The original Google provider has a deleted OAuth client and was preserved. Unknown provider acknowledgements must be inspected against the dispatch journal before retrying; this test launcher is not a durable fleet reconciler. The $10/day envelope is a planning limit, not a provider spending cap.

Automatic PR admission, durable provider provisioning/publication, TTL cleanup, general machine preview grants, arbitrary app builds, tenant fleet isolation, production promotion and latest-schema coordinated recovery remain separate gates. The retained local installation is not upgraded by these source changes or disposable proofs.

## Product account profiles and operator storage

Instance settings → Infrastructure connections → Add Cloudflare account saves an account-scoped API token using the existing encrypted, immutable profile versions. The API origin is fixed; Cloudflare profiles cannot carry database/S3 credentials, insecure transport or arbitrary destinations. Changing accounts requires a replacement credential. Management tokens do not activate CI object storage, authorize inference or configure an agent runtime.

Test checks Workers, R2, D1 and Artifacts read access independently without creating resources. Without a selected Artifacts namespace it probes namespace discovery; with one it probes that namespace's repository collection. Each operation has a bounded response and time limit, refuses redirects, and returns only service/state/scope/status. Read availability is separate from deployment authority.

A current Golf installation administrator who also has ordinary repository management access can open Repository settings → Environments → Cloudflare resources. New resource allocation creates exactly one empty D1 database and one private default-jurisdiction R2 bucket in the selected saved account. This is an explicit operator storage allocation, not a deployment, preview or enforcement of the environment's deployment-approval rules. Every creation requires the current administrator password, repository identity/access revision, exact environment/profile versions and a new original operation UUID. Browser cookies and same-origin checks are required; API/PAT/OAuth delegation is refused. The portable core remains usable without these resources.

Migration093 journals immutable Golf/native actor, forge, repository/owner, environment/profile versions, account and input identity before provider effects. Each dispatch and acknowledgement is retained with an append-only event. The database fences concurrent owners and permits one unresolved allocation per environment, ten unresolved pairs per workspace and at most1,000 historical operations per workspace. These bounded operator limits are not the SaaS workspace allocation model or a monetary billing cap.

Names are derived solely from the original operation UUID. Existing same-name resources cause refusal without adoption or deletion. Creation uses no provider retry, retains unknown effects and never replaces an original operation automatically. READY requires independent exact D1 ID/name and R2 name/creation-date readbacks, disabled managed public access, no custom R2 domains and fresh authority/version checks. Losing authority, changing versions or losing the database owner stops subsequent effects. An expired dispatch becomes UNKNOWN on inspection; it is never redispatched.

Remove resources uses only the original operator's acknowledged identities and original encrypted profile/account. Fresh administrator password/session authority remains mandatory. Compensation may remove those exact resources after repository deletion or environment changes; it cannot adopt an unknown database ID or unacknowledged bucket. R2 creation dates prevent deletion of an external same-name replacement. An empty-bucket DELETE never recursively removes objects. Exact GET404 establishes removal; denied, partial or ambiguous outcomes remain inspectable and retain the allocation fence. History is retained after cleanup and downgrade refuses retained operations.

The UI saves only scoped original UUID/version metadata in tab storage before dispatch; secrets stay in ephemeral form state. Reload/ambiguity offers original inspection without creation replay. A missing original receipt plus a fresh authorized inventory permits explicit clearing of the absent tab intent; the server's live environment fence still prevents duplicate allocations. Lost authority masks private data, and sign-out clears other actor intents.

Run the maintained checks from the repository root:

```sh
make qualify-cloudflare-product
python3 scripts/cloudflare-product-smoke.py --live --profile golf --account-id ACCOUNT_ID
npm --prefix web run build
python3 scripts/cloudflare-product-smoke.py --browser --profile golf
```

The source mode owns one temporary PostgreSQL container and runs real database-backed authority/replay/concurrency/partial-effect checks with the race detector. Live mode mints one twenty-minute account-scoped D1/R2 token through native CLI OAuth, exercises the actual Golf RPC/encrypted-profile consumer, immediately removes the resources, independently verifies native absence, and revokes that token and its short-lived cleanup helper. No token values are printed or retained. Recovery may delete only acknowledged IDs/creation dates in its private original receipt; lost acknowledgements are reported rather than adopted by discovery.

Browser mode exposes an isolated loopback Golf fixture through a temporary native quick tunnel for at most five minutes. Its native repository identity is controlled and it receives no live provider credential. T3's collaborative browser exercises actual handlers/forms with a placeholder token; an independent browser-proof receipt is required before acceptance. Closing the test stops both tunnel and database. SIGINT/SIGTERM runs owned cleanup; child deadlines kill their process groups. Abrupt host death still requires reconciliation from the private ownership journal. Every mode leaves owner-only evidence in `.tmp/cloudflare-product/` and exits nonzero if teardown is unconfirmed.

General application build/configuration plans, managed bindings/secrets, automatic preview fleets, tenant credentials and latest-schema coordinated restore remain separate acceptance work. The migration094 operator preview above has its own native admission gate. Source migration093 and these disposable proofs do not upgrade retained localhost/schema091.

## Operator account inspection

Build `go build -o bin/golf-server ./cmd/golf`, then run:

```sh
bin/golf-server cloudflare inspect --account-id ACCOUNT_ID --namespace APPROVED_NAMESPACE
```

Without `--profile`, credentials come only from the operator's `CLOUDFLARE_API_TOKEN` environment variable. Alternatively, use an authenticated named Cloudflare CLI OAuth profile:

```sh
bin/golf-server cloudflare inspect --profile golf --account-id ACCOUNT_ID --namespace APPROVED_NAMESPACE
```

This invokes the installed `cf` without opening its credential files. Profile inspection first checks `auth whoami`: authenticated/valid OAuth identity, selected profile filename and membership of the selected account. Environment token/global-key/email overrides are refused; a CLI-reported `.env` token or different profile also fails before service reads. Each subprocess pins the selected account and disables telemetry. Profile names use 1–63 ASCII alphanumeric/underscore/hyphen characters, starting alphanumeric. The verified CLI is `1.0.0-beta.13`; changed identity output fails closed until qualified. OAuth login/refresh remains the CLI's responsibility and may update its own local credential state.

The command does not accept a token argument or persist credentials. It runs without starting Golf or connecting to PostgreSQL. Product saved R2 profiles remain separate S3 credentials; management tokens use the separate versioned/encrypted product contract above.

Direct API mode performs exactly three GET operations against `https://api.cloudflare.com/client/v4/accounts/ACCOUNT_ID`: Workers scripts, one default-jurisdiction R2 bucket page, and one repository page in the selected Artifacts namespace. Profile mode performs three bounded CLI reads after identity inspection: Workers scripts **search** with `--per-page 1`, R2 buckets list with `--per-page 1`, and Artifacts repositories list with `--namespace NAME --limit 1`. Its Workers scope is `scripts_search_page_only`. Neither mode traverses pagination or performs provider-resource writes, Git token minting, deployment, creation or deletion.

The JSON report uses `golf.cloudflare.inspection.v1`, retaining selected account/namespace, check time, per-operation scope, available HTTP status and one bounded state: accessible, denied, not_found, rate_limited, redirect_refused, invalid_response or unavailable. CLI failures use `unavailable` without parsing human-readable stderr for HTTP status; successful CLI output must have the documented collection shape. Provider messages, names, response bodies and tokens are excluded. Exit is nonzero when any probe fails, after emitting the per-service report. Cancellation emits no partial success report. Invalid configuration/arguments and output errors are sanitized.

Each operation has a ten-second deadline, a 2 MiB output/body bound and no Golf retries. Subprocess cancellation and excess output kill the CLI process; pipe waits are bounded. Direct API mode refuses redirects, disables ambient HTTP proxies and requires the documented JSON envelope and collection shape. In profile mode, HTTP behavior belongs to the installed CLI; Golf discards stderr. Accessible establishes that read operation only: it proves neither deployment/write permissions nor billing/availability of all services, anonymous privacy, a full inventory or tenant authorization.

Live Artifacts returned a successful empty repository collection for a namespace absent from namespace discovery. A successful list is therefore not evidence that the namespace has been provisioned. Create/readback and Git qualification remain separate operations.

Sources: [Workers scripts](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/list/), [R2 buckets](https://developers.cloudflare.com/api/resources/r2/subresources/buckets/methods/list/), [Artifacts REST](https://developers.cloudflare.com/artifacts/api/rest-api/).

## Private Worker binding probe

`cloudflare/qualification/src/worker.mjs` exposes authenticated `GET /inspect`. It requires a 32–256 character random URL-safe `GOLF_PROBE_TOKEN` secret and compares hashed bearer credentials without returning or logging them. Unknown/query-bearing routes and write methods are refused. Public HTTP is refused; loopback HTTP is supported for local development. Every response is no-store with no CORS grant.

The Worker independently checks `EVIDENCE.head(GOLF_PROBE_OBJECT_KEY)` on an operator-selected existing R2 object and `ARTIFACTS.list({limit: 1})` in its bound namespace. It returns only fixed state/scope observations, excluding object/repository metadata and contents. Missing binding, missing object, malformed response, provider error and timeout cannot report success. Binding waits are bounded to five seconds; the underlying read RPC may finish after a timeout because the binding interface does not expose cancellation.

Copy `cloudflare/qualification/wrangler.jsonc.example` to a locally ignored config with the approved actual namespace, bucket and object key. The example disables workers.dev and preview URLs and adds no public route. Set `GOLF_PROBE_TOKEN` through the provider's secret mechanism, not config or source. Local generated configs are ignored. Deployment and invocation through a private service binding or separately qualified Access route require the real selected account/toolchain. No installation, login, deployment or resource mutation is part of this source check.

This is an operator credential, not a Golf user session, repository-reader grant or deployment broker. Before any product endpoint, use the native authority contract and actual Zero Trust/repository authorization. Sources: [Artifacts binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [R2 Worker API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/).

## Local validation

```sh
make cloudflare-check
```

Go checks exercise selected-account read-only requests, partial failure, malformed and oversized responses, credential redaction, refused redirects, invalid inputs, cancellation and command dispatch. Native subprocess checks also cover account pinning, profile/token ambiguity, identity refusal before service reads, output bounds and cancellation without a partial report. ## Disposable live qualification

```sh
python3 scripts/cloudflare-foundation-smoke.py --profile golf --account-id ACCOUNT_ID
```

This explicitly mutates the selected account. Use an authenticated operator profile with Workers Paid/Artifacts, R2 and temporary user-token permissions. The runner verifies profile/account identity, refuses environment credential overrides and creates a fresh `golf-cf1-YYYYMMDD-random` Worker, private bucket and Artifacts namespace. Exact ownership and source hashes are journaled before writes under owner-only, ignored `.tmp/cloudflare-foundation/`. It never opens the CLI's credential files, executes imported source or changes existing DNS, repositories, product capability flags or localhost.

The native `cf 1.0.0-beta.13` toolchain supplies build-output utilities and OAuth. `prepare.mjs` is intentionally version-pinned: beta.13's generated fork command consumes `name` as the source path parameter even with `--body`, dropping the required destination name. Fork mode uses the already-installed SDK's `additionalBodyParameters` to send the documented destination name while retaining native named-profile authentication. Requalify these internal exports when upgrading the CLI. No SDK or bundler dependency is added to Golf.

The proof exercises the existing Golf S3 store against real R2: immutable source/artifact create and replay, conflicting content without overwrite, exact verified readback, size/hash rejection, independently corrupted artifact denial, four simultaneous conditional writers with exactly one winner, anonymous denial and wrong-key denial. The fixture is a deterministic 10 KiB tar, with four possible cleanup keys. Fresh bucket credentials have a short activation delay; only read-only bucket probes poll, bounded to 15 seconds. R2's unsigned S3 request returns HTTP400 `InvalidArgument/Authorization`; the check admits only that precise denial or HTTP401/403, rather than treating any400 as privacy evidence.

Artifacts imports a shallow public `octocat/Hello-World` baseline. Independent native Git resolves and verifies its selected commit and tree before/after import. A separate writable fork starts at that commit, accepts one qualification commit via a fork-scoped writer, and a fresh reader clone verifies the exact proposal commit/tree. Anonymous access, read-token writes, cross-repository reads and new requests after explicit reader revocation are denied; parent refs remain unchanged. Git credentials are bounded opaque ASCII and passed only in child-process environment headers, with ambient Git configuration, credentials, hooks, proxies, traces, redirects and prompts disabled. Automatic create/import credentials are checked usable before deletion and denied after deletion; an opaque expiry remains an explicit evidence limitation.

The isolated Worker temporarily enables workers.dev for operator bearer-authenticated HTTPS invocation. It uses real R2/Artifacts bindings and verifies anonymous/wrong-token denial, authenticated accessible observations, refused writes/query paths, metadata omission and no-store responses. Fresh workers.dev platform404s receive a shared 30-second readiness bound for these exact side-effect-free probe requests (including the refused method); Worker responses and deployment/configuration failures are not retried. Preview URLs remain disabled. This qualification endpoint is reachable from the Internet with an operator secret; it is **not a Zero Trust protected repository-reader preview**. The ordinary Wrangler example remains private by default. Product Access/DNS/reader revocation are separate acceptance gates.

Cleanup reconciles only the fresh owned namespace, revokes known Git-token IDs, removes owned repositories and enumerated owned object keys, then deletes the empty bucket/namespace and Worker. Exact resource GET404s are required. No broad bucket purge or namespace deletion with references is used. Auto-issued Git credentials must also fail new requests after repository removal. Runtime secrets stay in process memory, except a mode0600 ignored Worker secret file removed immediately after deployment.

The CLI OAuth login can mint user tokens but its user-token DELETE route returned403. Cleanup therefore creates a **five-minute current-user API Tokens Read/Write credential**, deletes only this run's exact R2 credential ID, verifies its GET404, self-revokes even when R2 cleanup fails, then verifies its own HTTP401. The provider policy covers the current user's tokens, rather than one token ID: this is an operator test-cleanup ceiling, never a product tenant credential broker. Its ID/expiry policy are reviewable; its value is never persisted. A cleanup failure keeps the overall command nonzero and the ownership receipt available for exact recovery. Abrupt process/host death cannot guarantee teardown; short credential TTLs and the persisted ownership journal support operator reconciliation.

The $10/day infrastructure-plus-AI envelope is planning policy, not a provider billing cap. The proof invokes no inference and uses one small Worker, four small R2 objects and two tiny Git repositories. It does not measure the account bill or qualify fleet-scale cost. Successful qualification requires both positive checks and verified teardown; failed attempts and corrective receipts are retained without rewriting them as passes.
