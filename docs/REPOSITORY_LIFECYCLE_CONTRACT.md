# Repository archive lifecycle: bounded first packet

This packet implements archive/unarchive source behavior, private durable operation inspection, local password step-up, and a shared Golf repository admission gate. It does **not** complete the Archive, transfer and deletion settings section. Namespace transfer/acceptance, deletion, backup/retained-data safeguards, full ingress fencing, crash reconciliation and schema 041 recovery remain required. No actual supported-native or served UI qualification has been run for this packet.

## Supported native boundary

Pinned Gitea 1.27.3 accepts an optional `archived` boolean through repository PATCH; its handler rejects mirrors, updates archive state, and may clean/restart native Actions schedules. The repository converter exposes `has_actions` through `UnitEnabled`, whose usual unit load filters globally disabled units. That response is a repository-unit observation, not a separate instance configuration attestation or an atomic scheduling fence. This packet refuses archive changes when `has_actions` is true or absent (`native_actions_unqualified`). Supported default Compose/Helm instance configuration separately disables native Actions; an actual disposable native fixture must prove the observed false flag without disabling Golf-managed Actions. [Native Edit handler](https://raw.githubusercontent.com/go-gitea/gitea/v1.27.3/routers/api/v1/repo/repo.go), [converter](https://raw.githubusercontent.com/go-gitea/gitea/v1.27.3/services/convert/repository.go), [unit load](https://raw.githubusercontent.com/go-gitea/gitea/v1.27.3/models/repo/repo_unit.go).

Golf sends exactly one supported native PATCH containing only `{ "archived": true|false }`, followed by independent supported native reads. It never writes native SQL, Git refs or repository files. The native path-addressed API has no qualified atomic repository-ID/revision CAS; before/after observations are not an external rename, permission, ref or source fence.

## Browser-only API and observations

`RepositoryLifecycleService` has three procedures:

- `GetRepositoryLifecycle(repository, repositoryId)` returns exact repository/owner IDs, the current semantic revision, native archived/mirror observations, current ownership/admin observation, local step-up availability, and conservative archive/unarchive availability with a reason.
- `ChangeRepositoryArchiveState(repository, repositoryId, ownerId, expectedRevision, optional archived, confirmationName, currentPassword, idempotencyKey)` requires the exact full name, current native owner with repository admin, a managed local Golf account, and its current password. Organization ownership is independently checked and rechecked. Global/site admin, direct collaborator admin and private-org visibility are not ownership substitutes.
- `GetRepositoryLifecycleOperation(repository, repositoryId, ownerId, idempotencyKey)` is a current-authority-checked, own-user status read. Restoring authority may reveal a retained historical record; historical success never grants a new native intent.

The local-only step-up profile is deliberate: OAuth reauthentication and delegated CLI/MCP/PAT mutation are not enabled. Browser Origin, cookie/session identity, current native authority and managed-account/session locks apply even to direct handler calls. An incorrect password before reservation carries `Golf-Lifecycle-Effect: none`; only a separate explicit corrected-password submission using the retained original key is allowed. Transport/storage/authority failures do not receive that marker.

The revision binds the existing full General semantic projection plus the optional native Actions-unit observation. It is a stale-form check, not native CAS. Archive/unarchive refuses mirrors, active/unresolved Golf work, pending lifecycle effects, and unqualified native Actions. Current-owner-only counts are record counts across managed families, not a number of unique jobs. A native out-of-Golf unarchive does not silently clear Golf's retained archived admission latch: `managed_archive_fence` blocks new lifecycle dispatch and requires separately qualified reconciliation.

## Durable intent and once-only dispatch

Migration 041 stores metadata only: Golf owner/native actor and forge, immutable native repository/owner IDs, original routing name, UUIDv4 key, requested archive state, expected revision, original state, input digest, phase and timestamps. Passwords, native response bodies and repository contents are never journaled. The key is globally unique for that Golf user; exact replay is status-only, and changed inputs fail.

Transitions are `RESERVED → REJECTED`, or `RESERVED → DISPATCH_UNKNOWN → SUCCEEDED`. A valid frozen intent refused before dispatch receives durable `REJECTED/preflight_refused`; it may be followed by a separate explicit new intent. `RESERVED` and `DISPATCH_UNKNOWN` block new effects and never resend, including after restart. There is no autonomous repair worker. Corrupt/malformed input, unavailable storage or lost authority is not fabricated as a terminal refusal.

The dispatch-unknown transition commits before PATCH. Success requires exact native IDs, requested archive state, full unrelated semantic-field preservation, acknowledgement/readback agreement, and current native/session ownership after the wait. Even an uncertain response rechecks current authority before returning private operation metadata. Any acknowledgement mismatch, accepted-but-lost response or storage fault remains unresolved; independent current state alone does not attribute success. The append-only phase history and exactly one successful scoped `source` invalidation contain metadata only. Replay, refusal and unknown emit no shared success activity.

## Golf-only admission and write fence

`golf_repository_lifecycle_lock(forgeURL, nativeRepositoryID, exclusive)` is a transaction-scoped advisory lock. Reservation/transition takes the exclusive lock. Admission/claim/heartbeat updates in live states take the shared lock and refuse unresolved operations or the latest successful archived latch.

Migration triggers cover workflow runs, coding tasks, reviewer runs, push materializations, issue/comment mutations, human overall review mutations, reviewer publication reservations and inline review publication reservations. Existing terminal/cancellation evidence remains writable; the active count includes legacy reviewer uncertainty. This is a shared SQL admission gate, not just a count preflight.

The supported forge HTTP hook additionally fences existing `/repos/OWNER/NAME/...` mutations and `/teams/ID/repos/OWNER/NAME` association writes. It resolves current native identity with the same credential before the SQL lock, holds a bounded shared lock until the response body closes, and releases on response error/cancellation. It does not recursively hold a SQL lock across its identity GET. Only an exact durable DISPATCH_UNKNOWN archive PATCH receives the private lifecycle permit. New-account/org/repository creation paths are not existing-repository writes.

Lock order is managed Golf user/session, then repository lifecycle lock for reservation; native HTTP admission holds only its bounded repository lock. Secrets 042 and other repository execution brokers must use the same function/order rather than inventing another gate. Repository-scoped connection/policy metadata may remain writable where it has no native effect; attempts to materialize/admit actual work are fenced at the covered rows. Full connection-ingress freeze, external Git/SSH/native jobs, unknown native writers and P0.8 remain open. No claim is made that SQL triggers stop an external actor or that a finished worker cannot have an external effect outside Golf.

## Shared settings consumer

The new settings panel leads with current native state and current-owner work observations. Archive/unarchive opens a short confirmation dialog using TanStack Form and shared global classes. Transfer/deletion stay visibly unavailable. Fallback metadata discovery pins the first authorized native repository ID; a replacement at the same address is refused rather than silently adopted.

Browser session storage contains only original operation identity/target/revision/state metadata, scoped to origin/user/native repository. It contains no password, native response body or success authority. Reload issues status reads only. Unknown or inaccessible receipts remain inspection-only. Exact success/refusal permits a separate explicit action after a current observation; success is labeled historical. An unsent full-name confirmation survives successful revalidation, while the password is cleared and private controls are hidden/inert. Denial/account/target changes abort waits and clear private display state; late callbacks are fenced.

## Evidence and remaining qualification

Source checks and a disposable PostgreSQL suite test once-only archive/unarchive, independent receipt binding, stale/step-up/ownership denial, durable unknown/read-only replay, postflight native revocation, native Actions true/absent refusal, external-unarchive drift, append-only metadata and response-close lock release. A waiting admission is refused after an exclusive lifecycle reservation commits; active unknown publication prevents archive. Browser fixtures exercise explicit confirmation, original-key password correction, reload/status-only uncertainty, malformed/replaced identity, live revalidation/privacy, keyboard cancellation, both themes and 1440/390 layout with actual font loading.

These are source/real-PostgreSQL and browser-fixture checks, not supported-native runtime qualification. The integration owner must register the service through Golf's existing managed-browser/no-store boundary, export its shared client, mount the panel without losing pending identities, regenerate combined schema/proto artifacts, and run a fresh exact-image native/browser fixture. Native scheduling/ingress races, crash repair, offline recovery, cross-namespace transfer, last-owner rules, deletion and backup policy remain acceptance work under the original full settings goal.
