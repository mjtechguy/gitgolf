# Gitea mutation boundary inventory

**Static inventory, 2026-10-02; Gitea 1.27.3. P0.8 remains open.** This is the route/background-writer input to [proposed ADR 0004](decisions/0004-protected-integration-enforcement.md), not an implemented gateway, exhaustive provider audit or passing enforcement test. It identifies operations that can change the source H, target B, candidate availability, approvals A, policy/identity P, evidence E or publication authority F. Both Golf infrastructure tracks need the same guarantees.

The source review used the pinned API/web routers and handlers linked below. A read-only request to the local provider reported `1.27.3`; its public `swagger.v1.json` had SHA-256 `a0baa9a766c22492bd8c45744157c611d3e95cfc0dc73d6f5d14f294cdddce38`. Swagger confirms documented API methods, but does not inventory web, Git, internal RPC or queued work. No provider configuration or data was changed for this inventory. Live results remain in the separate [protected-write qualification](GITEA_PROTECTED_WRITE_QUALIFICATION.md).

## Current installations do not mediate these writes

| Current route into the provider | What exists today | Consequence for protected publication |
| --- | --- | --- |
| Compose host ports | [compose.yaml](../compose.yaml) publishes Gitea HTTP at loopback `3001` and SSH at loopback `2222`. Golf uses `http://gitea:3000` directly. | Local users and callers with network access use native Gitea without a Golf mutation barrier. Loopback limits reachability; it does not implement that barrier. |
| Helm HTTP ingress | When enabled, the [ingress template](../deploy/helm/golf/templates/ingress.yaml) routes the Gitea hostname's whole `/` prefix to Gitea. | Native web/API/Git HTTP routes remain reachable through that hostname, subject to Gitea permissions. This is not an OAuth-only allowlist. |
| Helm Services/policies | The [Gitea Service](../deploy/helm/golf/templates/gitea.yaml) exposes HTTP and SSH within the cluster. [Network policies](../deploy/helm/golf/templates/networkpolicy.yaml) constrain peers/ports, and configured ingress peers can reach HTTP/SSH. | L4 peer admission does not distinguish a read from a merge or settings mutation. An admitted peer still bypasses proposed publication admission. External Gitea remains operator-controlled. |
| Current Golf backend | The generated API implements reads and user repository creation. [RPC handling](../internal/server/rpc.go) applies session/Origin checks; the [forge client](../internal/server/forge.go) uses the caller's credential. | These checks preserve current authorization, but no publisher reservation, policy-generation barrier or provider-side authority epoch exists. Internal Golf mutations would also have to join the managed boundary. |
| OAuth and native credentials | A configured public Gitea origin hosts sign-in/consent; users may also possess native web sessions, PATs, OAuth grants, SSH/deploy keys or Basic-auth credentials. | Restricting one Golf credential does not remove the same account's alternate provider entry points. A fully mediated profile must control ingress regardless of credential type. |
| Operators and background jobs | Container/Kubernetes administrators can reach provider processes/volumes; Gitea has internal queues and scheduled work. | Emergency access and previously admitted work must invalidate or quiesce protected operation eligibility. Neither a private hostname nor disabling a button establishes exclusivity. |

“Unmediated” here means outside the **proposed Golf publication barrier**, not unauthenticated or necessarily permitted by Gitea. No new bypass probe was run for this document.

## Classification required before admission

Use a closed allowlist of normalized method, canonical route, operation/body and actor, resolved to immutable repository/organization/user IDs. Unknown routes, methods, fields, transport verbs and provider versions fail closed for the managed profile. A suffix blocklist for `/merge`, a read-only token, or a blanket GET allowance is insufficient.

For each admitted mutation, declare the exact resource set it can affect: both fork source and base, branch names/full refs, PR/review identity, membership/protection generations, credentials and evidence producer. Acquire the applicable reservations in a stable order and retain them until the provider operation is conclusively complete. A request whose outcome is unknown remains uncertain; timeout, TCP close or lost Golf lock is not proof that provider execution stopped.

Canonicalize once consistently with the actual upstream router: test optional `.git`/wiki repositories, case aliases, renamed-owner/repository redirects, slash-containing branches, encoded separators, duplicate separators/query/body fields and mount prefixes. Ref-bearing JSON/form fields can select a different branch from the URL. Do not forward arbitrary user-controlled headers such as internal authentication, proxy-identity or `Sudo`, or silently follow credential-bearing redirects. These are proposed gateway obligations, not controls claimed by this document.

## OAuth is a narrow, stateful exception

The existing Golf flow must still work after the raw provider becomes private. The following is a **candidate allowlist requiring browser/API tests**, not deployed configuration. Do not expose all `/user/*`, `/login/*` or `/user/settings/applications/*` merely to fix a broken sign-in.

| Route and caller | Candidate allowance and boundary |
| --- | --- |
| Browser `GET,POST /user/login`; required static assets | Existing password login. Preserve session/CSRF/cookie/redirect behavior; restrict the return destination to the approved authorization flow. Gitea login produces a native session, so other provider routes must remain denied with that cookie. |
| Browser `GET /login/oauth/authorize`, `POST /login/oauth/grant` | Exact Golf client ID, registered callback, allowed scopes and S256 flow. Native router also supports POST authorize; deny unless deliberately qualified. Authorization is not a stateless read: it updates provider authorization state and can issue a code. |
| Golf backend `POST /login/oauth/access_token` | Code exchange/rotating refresh, routed only to the configured provider. This creates credentials and must not be a generic untrusted proxy. Existing state/PKCE/secret controls still apply. |
| Browser `GET /user/settings/applications`; `POST /user/settings/applications/oauth2/{id}/revoke/{grantId}` | Narrow user-owned grant revocation for the configured app. The same settings namespace contains PAT creation, app create/edit/delete and secret regeneration; those are not required just to revoke consent and must not be wildcard-allowed. |
| Browser `GET /user/logout` | Explicit session termination, despite GET. Does not revoke provider tokens. Qualify login/consent redirects without permitting arbitrary post-login navigation to write pages. |
| MFA/recovery/federated provider routes | TOTP/scratch and WebAuthn routes exist under `/user/two_factor` and `/user/webauthn`; external login/account-link/recovery routes are additional state machines. Add only for explicitly supported login configurations with separate tests. Never disable MFA to fit the minimal allowlist. |
| OIDC discovery/keys/userinfo/introspection | Separate native capabilities; Golf's current code/PKCE login does not need a blanket OIDC namespace allowance. Decide exact service callers/methods or deny. |

Sources: [login/authentication route mounts](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/web/web.go), [provider authorization/token handler](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/web/auth/oauth2_provider.go), [application/grant settings](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/web/user/setting/oauth2_common.go).

The already-run real OAuth smoke established a relevant limitation: Gitea's confidential-client authorization reuses an existing narrower grant without displaying new consent. Refresh and another sign-in do not add organization scope. Explicitly revoke the user's authorized Golf grant, then obtain fresh consent. That credential lifecycle must remain possible through the managed auth boundary. Revocation has the provider's normal lifecycle; it does not fence an already accepted publication process.

## Background and process writers

| Writer / trigger | Why ingress rules alone cannot settle it |
| --- | --- |
| Native scheduled auto-merge | A stored schedule and its queue can publish later when status/review conditions change. Review/status notifications enqueue checks. Deny new schedules **and** cancel/reconcile existing schedules and already-running handlers before protected eligibility. Disabling Actions does not disable native auto-merge. [Auto-merge](https://github.com/go-gitea/gitea/blob/v1.27.3/services/automerge/automerge.go), [notifications](https://github.com/go-gitea/gitea/blob/v1.27.3/services/automerge/notify.go). |

[PR check service](https://github.com/go-gitea/gitea/blob/v1.27.3/services/pull/check.go). |
| Post-receive PR/ref/review processing | Accepted pushes drive PR ref updates and asynchronous stale-review handling. An HTTP push response does not prove all downstream bookkeeping has settled. [Push processing](https://github.com/go-gitea/gitea/blob/v1.27.3/services/pull/pull.go), [post-receive](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/private/hook_post_receive.go). |
| Pull/push mirrors | Cron and sync-on-commit/queued work perform fetches or external pushes. [Defaults](https://github.com/go-gitea/gitea/blob/v1.27.3/modules/setting/mirror.go), [cron](https://github.com/go-gitea/gitea/blob/v1.27.3/services/cron/tasks_basic.go), [sync](https://github.com/go-gitea/gitea/tree/v1.27.3/services/mirror). |
| Migration/restore/adoption | API migration uses a provider lifetime context; request cancellation cannot be assumed to stop it. Web migration/task processing, restores and repository adoption can materialize refs/settings independently of a later gateway decision. Do not admit partially imported or recovering repositories. [Migration handler](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/api/v1/repo/migrate.go), [startup services](https://github.com/go-gitea/gitea/blob/v1.27.3/routers/init.go). |
| Native Actions/runners and external automations | Jobs may use write-capable tokens, publish statuses or call Git/API. Golf currently sets native Actions disabled. A future enablement requires scope/evidence mediation and revocation of already-issued credentials, plus fencing accepted work. Webhooks/incoming integrations are triggers, not trusted evidence producers by default. |
| Custom hooks, operator jobs and storage maintenance | Hooks run with forge OS authority; pinned custom-hook default is disabled, but retained config/hooks must be inventoried. | In-flight receive/merge child processes | Losing a client connection, Golf process or reservation does not demonstrate that Gitea's accepted child has stopped. Recovery must establish supported process/node/storage quiescence before another overlapping writer proceeds. Neither this source review nor a new epoch stored only in Golf proves that condition. |

## Private-fork observation and PR finalization

Static source identifies two promising but limited supported operations for the separate publisher experiment:

- The single-PR detail converter opens the actual head repository and reads its live branch when it exists; the list converter and deleted/missing-head fallbacks may use target-local PR refs. A base-only actor's precise private-fork visibility, exact repository/ref identity and object fetch must be tested. Do not equate a returned SHA from any PR endpoint with authoritative live fork H. [PR conversion](https://github.com/go-gitea/gitea/blob/v1.27.3/services/convert/pull.go).
- `POST P/merge` with `Do: manually-merged` and `merge_commit_id: C` invokes a separately checked bookkeeping path. The service requires the merge style to be enabled and C to exist in the target branch's history, then records merged state. That is not a requirement that the tip still equals C, that C has the intended parents, or that source H/reviews remain current. Golf must verify its full invariant and reconcile this bookkeeping idempotently after supported publication. [Manual merge implementation](https://github.com/go-gitea/gitea/blob/v1.27.3/services/pull/merge.go).

These observations are hypotheses to qualify with ordinary scoped actors, not permission to read a private fork through an administrator or to mark an arbitrary ancestor as the tested integration.

## Required executable closure

| Gate | Evidence still required |
| --- | --- |
| Canonical route classifier | Table-driven positive/negative method/path/query/form/JSON tests for every admitted operation; unknown fields/routes/provider-version drift denied. Include Git receive, issue/PR aliases, slash refs, transfer/rename aliases and credential variants. |
| Real deployment isolation | Ordinary browser/PAT/OAuth/SSH/deploy-key actor cannot use direct ports, alternate hosts, ingress paths, internal endpoints or pod/network access to bypass the boundary. Show legitimate mediated reads/source pushes and OAuth consent/revocation still work. |
| Short final reservation interval | Pause after final H/B/P/A/E reads and race each applicable source/base/review/membership/protection mutation; each orders before validation or after publication, including private forks. |
| Background admission/eligibility | Demonstrate absence or safe settlement of schedules, mirrors, migration/import tasks, custom hooks and already-issued credentialed work. A config flag or empty HTTP request queue alone is insufficient. |
| Interrupted publication | Pause an accepted provider write, lose the issuer/lock/connection, start a replacement, and prove overlapping writes stay blocked until supported quiescence plus reconciliation. Explicitly reject unsupported automatic takeover. |
| Exact candidate and finalization | Compare final branch C, parent/tree identity and trusted evidence; recover response/bookkeeping loss without blind retry or duplicate finalization. Test private-fork fetch/head deletion/change and manually-merged API limits. |
| Emergency and upgrade behavior | Settings/identity/operator access invalidates eligibility; route and queued-task inventory changes are reviewed on every provider upgrade. No unqualified instance or unmanaged connected fork inherits the guarantee. |

Until those checks pass and ADR 0004 is accepted, the inventory supports implementation planning only. No protected publisher, generic gateway, SSH mediation or full managed deployment has been delivered by this document.
